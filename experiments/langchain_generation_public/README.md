# LangChain 생성 연결 비교 실험

기존 사용자 답변 생성의 모델 호출 부분을 LangChain으로 연결했을 때 입력·출력과 후처리를 유지할 수 있는지 확인합니다. 4차 회의에 따라 기존 담당 업무와 병행 가능한 선택적 실험이며, 운영 도입은 필수 목표가 아닙니다.

## 변경 범위

```text
기존 요청 준비 → ChatPromptTemplate → ChatOllama → 응답 형식 변환
             → 기존 JSON 해석·출처 복원·교정 후처리 → 기존 생성 결과
```

기존 OllamaGenerator의 transport 주입 지점을 사용합니다. 모델 호출은 실제 LangChain 체인으로 교체하며 기존 생성 함수 전체를 감싸기만 하는 구조는 아닙니다. 프롬프트 원문 작성과 후처리는 기존 코드를 재사용하므로 모든 단계를 LangChain 구성요소로 분리한 구현은 아닙니다.

운영 서비스 연결, 원문 지시문, 공통 requirements, 검색·DB·UI는 변경하지 않습니다. 원문 생성 결과를 화면에 직접 전달하지 않습니다. 다른 평가 실험의 모델·자료·점수를 변경하거나 합산하지 않습니다.

## 파일

| 파일 | 역할 |
|---|---|
| generator.py | 명시한 모델·주소로 생성하는 실험 구현 |
| compare.py | 기본은 계획 출력. 실제 실행은 명시적 옵션으로 제한 |
| review_run.py | 로컬 결과의 호출 수·입력·원문/최종 유형 비교. 사실성 채점 아님 |
| test_*.py | 가상 모델 응답과 기존 저장소 fixture를 이용한 오프라인 검사 |
| requirements.txt | 별도 실험 환경용 직접 의존성 |

개인 A40, Ollama 0.34.0, qwen3:8b Q4_K_M을 사용했습니다. 모델 digest는 500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41입니다. temperature 0, think false, stream false, general 수준, num_predict 640. 첫 실행과 재실행의 Python 패키지 환경은 달랐으므로 완전히 동일한 환경의 전후 실험은 아닙니다.

두 번째 실행의 실제 원문을 main/PR #5 후처리에 재입력했을 때 첨가 표현 두 응답이 main에서는 교정으로 바뀌고 PR #5에서는 정상 유지됐습니다. 이 후처리 비교에는 추가 모델 호출이 없었습니다. 다른 사례를 포함한 8개 재처리 결과가 저장된 최종 필드와 일치했습니다.

이 PR에는 실제 모델 원문·서버 로그·개인 환경 기록을 포함하지 않습니다. 위 내용은 로컬 실측 요약이며 이 PR만으로 실측 결과를 재계산할 수 없습니다. 포함한 테스트는 가상 응답 검사이고, 공개용으로 분리한 코드 자체는 실모델 재실행하지 않았습니다.

## 확인된 한계

- 두 방식 모두 근거에 없는 역할·방문객 설명을 덧붙이는 경우가 남았습니다. LangChain 도입에 따른 품질 향상을 입증하지 않았습니다.
- 방문객 질문의 원문 선택지에는 근거 없는 숫자가 있었으나 기존 후처리가 최종 결과에서 제거했습니다.
- 생성기 유보와 서비스의 근거 판정이 충돌하면 generation_error가 될 수 있습니다. 생성기 단독 반환을 실제 UI의 정상 유보와 동일시하지 않습니다.
- 작은 가상 자료·단회 비교입니다. 초기 적재·캐시·출력 길이가 달라 속도 우열을 판단하지 않습니다.
- 요청마다 ChatOllama 객체를 만드는 실험 구현입니다. 운영 반영 전 클라이언트 수명·실패 처리·부하·대상 환경을 확인해야 합니다.
- 별도 전체 의존성 환경에서 import와 오프라인 검사를 수행했지만 Linux 배포·실브라우저·실제 평가 점수의 동등성은 미확인입니다.

## 오프라인 실행

공개용으로 분리한 폴더의 검사 **35개 통과**, 기본 실행의 모델 호출 0회를 확인했습니다. 과거 로컬 통합 검사 184개와 범위가 다르므로 같은 수치로 제시하지 않습니다.

저장소 루트, Python 3.12 별도 환경에서 사용합니다. 아래 설치는 실험 환경에만 수행합니다.

```powershell
python -m pip install -r experiments/langchain_generation_public/requirements.txt
$env:PYTHONPATH='src;.'
python -m pytest experiments/langchain_generation_public -q
python -m experiments.langchain_generation_public.compare
```

기본 실행은 계획만 표시하며 모델 호출 0회입니다. 가상 자료는 실제 문화유산 사실성 평가 자료가 아닙니다.

## 실제 실행 — 현재 PR의 검토와 별도

현재 대상 코드와 모델을 관련 담당자와 확인한 후 실행합니다. 기본 8회, repeats는 1~3으로 제한합니다. 모델 실행은 GPU 자원을 사용하고 가상 질문·근거를 설정한 서버로 전송합니다.

```powershell
$env:PYTHONPATH='src;.'
# LANGCHAIN_EXPERIMENT_BASE_URL은 로컬에서 설정. .env 파일은 읽지 않음.
python -m experiments.langchain_generation_public.compare --live --model '<모델명>' --expected-commit '<현재 검증할 전체 SHA>' --output '<새 결과.jsonl>'
```

지정 commit과 checkout이 다르거나 서비스 코드에 미기록 변경이 있으면 호출 전에 중단합니다. 결과 파일은 덮어쓰지 않고 호출별로 저장합니다. 오류 메시지 원문·접속 URL·헤더는 저장하지 않습니다. 모델 출력 내용은 로컬 파일에 저장되므로 개인 자료를 입력하지 않습니다.

## 검토 요청

1. 생성 담당: 기존 입력·출력·후처리 재사용 범위가 적절한지.
2. 평가 담당: 독립 실험 범위와 품질 한계가 명확한지. 기존 평가 변경을 요청하는 PR은 아닙니다.
3. 팀: MVP 우선 원칙에 따라 실험 자료로 보관하는 방향이 적절한지.

이 PR의 병합은 운영 LangChain 도입이나 추가 GPU 실행 승인을 의미하지 않습니다.
