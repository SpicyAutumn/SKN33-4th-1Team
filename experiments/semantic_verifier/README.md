# AI 답변 검수 방식 비교 — 사용 안내

이 도구는 **AI가 답변의 오류를 제대로 찾아내는지** 확인하기 위한 실험 도구입니다. 실제 서비스의 답변 기능을 바꾸지는 않습니다.

- **A(기존 방식):** 원문을 보고 답변의 한 문장이 맞는지 검사하게 합니다.
- **B(보완 방식):** A의 지시에 사람의 관계나 사용 범위를 함부로 넓히지 말라는 설명을 추가합니다.
- **이번 결론:** B의 개선이 확인되지 않아 실제 서비스에는 적용하지 않습니다. A도 오류를 놓쳤으므로 믿고 자동 판정하도록 승인한 것은 아닙니다.

## 먼저 읽을 핵심

| 하고 싶은 일 | 읽을 부분 | AI 사용료 발생 여부 |
| --- | --- | --- |
| 실험 결과 이해 | [결과 요약](../../docs/SEMANTIC_VERIFIER_EXPERIMENT.md) | 없음 |
| 코드가 작동하는지 확인 | 아래 'AI를 호출하지 않는 사전 검사' | 없음 |
| 실제 모델로 다시 비교 | '실제 호출 전 승인과 한도' | 서버 사용료 발생 가능, 별도 승인 필요 |
| 저장된 응답 검수 | '저장된 결과를 사람이 확인하기' | 없음 |

```text
제공 원문 + 검사할 답변 한 문장
              │
       ┌──────┴──────┐
       ▼             ▼
   A: 기존 지시   B: 보완 지시
       └──────┬──────┘
              ▼
       판정·인용·설명 저장
              ▼
  코드 검사: 인용이 원문 그대로인가?
              ▼
  사람 검수: 판정과 설명도 타당한가?
```

원문을 정확하게 복사한 인용이라도 **그 인용으로 잘못된 결론을 내릴 수 있습니다.** 따라서 코드 검사와 사람 검수는 별도 단계입니다.

## AI를 호출하지 않는 사전 검사

저장소 루트에서 Python 3.12로 실행합니다. 오프라인 검사는 표준 라이브러리만 사용합니다.

```powershell
python -X utf8 -B experiments/semantic_verifier/runner.py --inputs experiments/semantic_verifier/example_inputs.json
python -X utf8 -B -m unittest discover -s experiments/semantic_verifier -p "test_*.py"
```

기본 실행은 모델 호출·결과 파일 생성이 없습니다. 테스트는 임시 폴더에 모의 결과를 기록하고 정리합니다. 합성 예시는 직접 작성한 장비·참가자·물건 이야기입니다. 역사 원문이나 과거 모델 응답이 아닙니다. 예시 ID는 실행 순서 확인용이며 과거 V01~V03의 실제 내용을 대신하지 않습니다.

## 파일별 역할

- runner.py: 입력 검증, 고정 순서, 요청 구성, 호출·중단·저장.
- transport.py: 명시적으로 승인된 loopback 연결만 허용. 프록시·환경 인증정보·리다이렉트·자동 재시도 사용 안 함. 최대 응답 4 MiB. 실제 실행 시 requests 필요.
- candidate.json / meaning_addendum.txt: 과거 비교의 A와 B 추가 지시. candidate.json의 상태·null 모델 값은 원본 후보 메타데이터이며 runner.py의 고정 모델·옵션을 사용함.
- report.py: 결과와 별도 정답 키를 오프라인으로 대조. 모델에는 키를 전달하지 않음.
- example_inputs.json / example_key.json: 합성 동작 확인 자료.

## 예제와 실제 평가 자료는 다릅니다

합성 예시와 별도로 research_evidence.json에 당시 원문 청크·주장·응답 문맥·확정 판정 및 두 세션의 실제 출력을 보존했습니다. [과정·출처·이용 범위](../../docs/SEMANTIC_VERIFIER_JOURNEY.md)를 먼저 읽어 주세요. 이 증거 파일은 실행 입력 스키마와 다르며 곧바로 --inputs에 넣지 않습니다. 모델 다운로드는 자동 수행하지 않습니다. 실제 재평가에는 이용 범위 확인, 입력 구조 변환과 별도 실행 승인이 필요합니다. 개인 환경·접속정보는 포함하지 않았습니다.

입력 스키마는 example_inputs.json을 참고합니다. 실제 자료는 kind를 reviewed_external로 하고 inputs에 V01~V03을 각각 한 번 넣습니다. 입력에는 정답·판정 이유·검수 메모를 넣지 않습니다. kind는 사용자 선언이며 검수 완료를 자동 입증하지 않습니다. 정답 키는 별도 파일로 보관하고 origin으로 실제 발췌와 작성 예시를 구분합니다.

해시는 로드한 자료·요청의 일관성 확인용이며 출처 허용이나 진본성을 증명하지 않습니다. 원본 실험 자료에 대한 기존 보존·해시 확인 절차는 이 공유용 도구가 자동 수행하지 않습니다. 입력 문자가 토큰 창에 맞는지도 실제 실행 전 확인해야 합니다.

## 실제 호출 전 승인과 한도

명시적인 --execute --approve-live, --base-url, --deployed-at, --environment-record, --output-root가 모두 필요합니다. 기본값으로 실제 호출하지 않습니다. 새 배포의 시간대 포함 시각을 사용합니다. 환경 JSON 필수 항목은 deployed_at, model_digest(전체 소문자 SHA256), ollama_version, gpu, driver, model_defaults입니다. 수동 관측 기록이므로 서버와 자동 비교했다고 해석하지 않습니다. 비밀키를 넣지 마세요.

실제 연결에는 requests가 필요하며 공유용 도구는 이 패키지를 자동 설치하지 않습니다. 기존 실험은 requests 2.34.2 / Python 3.12.13을 사용했습니다. 새 코드의 실서버 동작은 미검증입니다. 추가 유료 실행은 별도 승인 후 진행합니다.

고정 순서: 준비 W00-A, V02-A, V02-B, V01-B, V01-A, V03-A, V03-B. 최대 7회, 요청 120초, 배포 45분 이후 신규 호출 중단. 실패하면 나머지는 미실행으로 보존합니다. 자동 재시도·자동 수정·서버 종료는 없습니다. timeout은 서버 추론 취소나 요금 차단이 아닙니다. 결과 보존 후 사람이 Pod을 종료해야 합니다.

결과에는 원문과 응답이 저장되므로 --output-root는 접근이 통제된 별도 폴더로 지정하고 커밋하지 마세요. 이전 live 결과 디렉터리에 덮어쓰지 않도록 고유 이름을 생성합니다. 요금 상한을 자동 보장하지 않으므로 배포 화면과 경과 시간을 확인해야 합니다.

## 저장된 결과를 사람이 확인하기

```powershell
python -X utf8 -B experiments/semantic_verifier/report.py --run <결과폴더> --key <별도정답JSON>
```

콘솔 JSON으로 원문·응답·판정·실패·미실행·시간을 표시하며 파일을 변경하지 않습니다. 준비 호출은 점수에서 제외합니다. 라벨 일치만으로 통과시키지 말고 다음을 사람이 확인합니다.

| 확인할 것 | 확인 방법 | 의견 작성 예 |
| --- | --- | --- |
| 판정 | 검사 대상 문장과 원문의 뜻을 비교합니다. | '범위를 넓혔으므로 맞다는 판정에 동의하지 않음' |
| 인용 | 복사한 원문이 해당 판단의 이유가 되는지 확인합니다. | '원문에는 존재하지만 이 주장과는 무관한 구절임' |
| 설명 | 원문에 없는 사람의 신분·관계·범위를 추가했는지 확인합니다. | '판정은 맞지만 설명에서 신분을 단정한 부분은 오류' |

전체 문서를 다시 작성할 필요는 없습니다. **문항 번호 + 동의/수정 의견 + 해당 표현과 이유**를 적으면 됩니다. 실행하지 못한 문항은 '미확인'으로 남깁니다.

## 용어를 쉽게 읽는 법

| 코드·문서 용어 | 쉬운 뜻 |
| --- | --- |
| 프롬프트(prompt) | AI에게 주는 지시문 |
| 주장 / 대상 주장 | 맞는지 검사할 답변의 한 문장 |
| 라벨(label) | '근거 있음', '원문과 충돌' 등의 판정 이름 |
| supported / contradicted | 원문이 뒷받침함 / 원문의 내용과 충돌함 |
| unsupported / meaning_weakened | 원문으로 확인하기 어려움 / 중요한 뜻이 약해짐 |
| needs_review | AI가 판정을 유보해 사람 확인이 필요함 |
| 합성 예시 / 모의(mock) 결과 | 코드 검사 목적으로 직접 만든 예제 / 실제 모델이 만든 것이 아닌 가짜 응답 |
| dry run / 오프라인 검사 | 모델을 호출하지 않고 준비 상태나 코드 동작만 확인 |
| 스키마(schema) | 입력·출력 파일에 들어갈 항목과 형식의 규칙 |
| 토큰(token) / 문맥 창 | 모델이 글을 처리하는 단위 / 한 번에 처리할 수 있는 분량 |
| 해시·digest | 내용의 동일 여부를 확인하는 식별값. 내용이 참이라는 보증은 아님 |
| loopback | 내 컴퓨터 주소로 연결. 서버 연결은 별도 SSH 통로를 이용 |
| timeout | 응답을 기다리는 제한 시간. 서버 종료나 요금 중단과는 다름 |

인용 실패는 자동 보정하지 않습니다. 모의 결과와 실제 결과, 실제 답변 발췌와 작성 예시는 구분합니다. 단회 개발 표본으로 일반 정확도·속도 우열을 주장하지 않습니다.

## 이력

PR 검토 보완: 출력 길이 제한으로 끝난 응답도 문항별 파일에 먼저 저장한 뒤 `truncated_or_incomplete`(잘렸거나 완료되지 않은 출력)로 분류합니다. 보고서에서 원문 출력과 `finish_reason`(모델 종료 사유)을 확인할 수 있습니다. 성공 처리·자동 재시도는 하지 않습니다. 네트워크 응답 자체가 완성되지 않은 경우에는 기존처럼 수집 실패로 처리하며 원시 통신 파일을 확인해야 합니다. GitHub 자동 검사에도 이 실험의 오프라인 테스트를 별도 추가했습니다.

공유용 구조는 과거 로컬 도구와 별도 구현이며 과거 결과를 이 코드로 생성했다고 주장하지 않습니다. 후보 프롬프트는 기존 내용을 보존했고 통신 모듈은 기존에서 가져온 뒤 위 PR 보완을 적용했습니다. 원본 로컬 도구·데이터는 변경하지 않았습니다. 공유용 테스트는 기존 66개 테스트와 별개입니다.

실험 결과와 검수 결론은 [결과 요약](../../docs/SEMANTIC_VERIFIER_EXPERIMENT.md)을 참고하세요.
