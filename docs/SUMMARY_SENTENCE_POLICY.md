# 핵심 요약 문장 정책

## 변경 이유

강강술래 검색 화면에서 요약이 정확히 240자 뒤의 `원형을 이루며`로 끝났다.
기존 Ollama JSON 스키마의 `summary.maxLength=240`과 일치하며, 프런트엔드는
요약을 그대로 표시한다. 글자 수 제한을 제거하고 완결된 1~2문장을 요청한다.

## 처리 규칙

- 글자 수 제한 없이 핵심 결론만 간결하게 생성한다. 세부 설명은 본문에 남긴다.
- PR #5의 정정 유형 정규화와 잘못된 동의 표현 제거를 먼저 수행한다. 근거 ID 검증 후 최종 요약을 선택하며, 요약 필드가 누락됐을 때도 정리된 본문을 사용한다.
- 근거 ID를 확인하지 못해 답변 또는 정정 답변이 근거 부족 안내로 바뀌면 요약도 같은 안내로 바꾼다.
- 문장 끝 기호 뒤의 공백 또는 문자열 끝을 기준으로 앞의 완결 문장 최대 2개를 사용한다.
- 요약 뒤의 미완성 구절은 제외한다. 요약에 완결 문장이 없으면 본문에서 최대 2개를 사용한다.
- 요약 필드가 없는 구형 응답도 같은 본문 대체 규칙을 적용한다.
- 문장 끝 기호가 없어도 `[가-힣]니다`(`입니다`, `합니다`, `춥니다` 등), `한다`, `된다`, `했다`, `됐다`, `있다`, `없다`, `이다`, `해요`, `돼요`, `예요`, `이에요`, `가요`, `나요`, `까요`로 끝나면 마지막 문장을 보존한다. 마침표나 사실은 덧붙이지 않는다.
- 요약과 본문 모두 문장 끝 기호 또는 지원하는 종결형이 없으면 생성 오류로 처리한다. `원형을 이루며`, `손을 잡고` 등은 본문 대체 또는 제외 대상이다.
- 이 규칙은 문자열 휴리스틱이다. Qwen이나 별도 판정 모델이 의미 완결성을 판정하는 기능을 추가한 것은 아니며, 모든 문법·약어·구어체를 포괄하지 않는다.
- 추가 LLM 호출은 없다. 기존 전체 생성 토큰 한도는 유지한다.

## 오프라인 검증

| 입력 | 변경 후 |
| --- | --- |
| 240자를 넘는 완결된 한 문장 | 원문 전체 유지 |
| 두 문장 뒤 `원형을 이루며` | 두 문장만 반환 |
| 완결된 세 문장 | 앞의 두 문장 반환 |
| 요약은 미완성, 본문에 완결 문장 존재 | 본문 문장으로 대체 |
| 소수 `3.5m` 또는 문장 끝 닫는 따옴표 | 내용 보존 |
| 요약과 본문이 모두 미완성 | 생성 오류 |

재현 명령:

```bash
python -m pytest -q --basetemp=.pytest_cache/summary-fix-tmp
python -X utf8 -B -m unittest discover -s experiments/semantic_verifier -p 'test_*.py'
```

결과: pytest 192개 및 subtest 55개 통과, semantic verifier 29개 통과.
위 결과는 최초 PR 작성 당시 결과다. PR #5 통합 후 검증은 아래에 별도 기록한다.
최초 pytest 실행은 Windows 임시 폴더 접근 권한으로 5개 setup 오류가 발생했으며,
저장소 내 임시 폴더를 지정한 재실행에서 전체 통과했다.

- 문장부호 기반 검사이며 한국어 문법·의미 완결성을 보장하지 않는다. 약어의 마침표 등은 오인할 수 있다.
- 전체 토큰 한도로 JSON 자체가 중단되는 경우는 기존 오류 경로를 따른다.
- 실제 팀 Ollama 모델로 `강강술래가 뭐냐`를 검색하는 품질 확인은 리뷰 시 필요하다.

### 실제 Qwen 검증 결과

- 사용자 승인 후 기존 `.env` 설정으로 6회 실행. 실제 반환 모델 ID `qwen3.8:27b`, temperature 0, think false, top_k 3, 기존 Hybrid 검색 경로. 일반 640/심화 1024 생성 토큰 한도 유지.

- 강강술래 일반 2회·심화 1회: 요약과 본문 완결. 일반 2회는 표현 차이가 있었지만 두 요약 모두 완결됐다.
- 경복궁 1400년 완성 단정: 1395년으로 정정하며 요약·본문 일치.
- 경복궁 완성 시각: 근거 부족 안내. 서비스 최종 요약과 본문이 같은 안내로 유지됨.
