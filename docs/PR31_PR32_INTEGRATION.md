# #31·#32 추가 질문 통합

## 변경 목적

#31은 선택지와 직접 수정 입력을 제공하고, #32는 선택한 대상·근거를 다음 요청에도 유지합니다. 두 PR의 `App.jsx` 추가 질문 영역 충돌을 #31에서 해결했습니다.

- 기반 main: `202c86a`(HTTPS 설정 포함)
- #31 원본: `56fd936`
- 함께 반영한 #32: `0df99f0`(검사 환경 보완 포함)
- 원격 #32 브랜치는 이번 통합 과정에서 변경하지 않았습니다.

## 유지한 기능과 연결 방식

| 상황 | 동작 |
|---|---|
| 동명이인 선택 후 재검색 | #32의 `clarificationFollowup` 결과를 유지해 `interaction_id`, `clarification_context`, `selected_source_chunk_ids` 전달 |
| 다른 선택지로 변경 | 선택한 대상과 근거를 새 선택으로 교체 |
| 선택 후 문장을 직접 수정 | 선택 정보를 해제하고 일반 질문으로 전달. 이전 문장으로 되돌려도 자동 복원하지 않음 |
| 여러 질문 중 하나를 선택 | #31의 분리 질문 문장을 그대로 사용 |
| 근거 부족 시 직접 질문 수정 | #31의 일반 재검색 흐름 유지 |
| 이전 대화 ID가 없는 자료 | 선택한 설명을 새 질문으로 전달하고 연결할 수 없는 근거 ID는 보내지 않음 |

화면에는 선택 유지 여부와 직접 수정 시 선택이 해제되는 이유를 안내합니다. #32의 질문 작성 도우미와 백엔드 검색·생성 기능 코드는 그대로 사용합니다.

## 확인 결과

- 프론트 테스트 28개 통과(선택 유지·교체·해제 등 새 테스트 6개 포함).
- 백엔드 API 테스트 11개 통과.
- 후속 질문 검사, 재검색 화면 검사, 제보·사진 검사, production build 통과.
- 브라우저에서 실제 `App`을 조작하여 두 번째 선택지의 근거 ID와 대화 정보가 요청에 포함되는 것 확인.
- 같은 화면에서 선택 후 직접 질문을 수정하면 이전 대화·근거 정보가 빠지는 것 확인.
- 검증 탭 콘솔 경고·오류 없음.

브라우저 검증은 개발 전용 `/clarification-review.html`에서 모의 응답을 사용했습니다. 외부 AI 호출이나 DB 저장, 실제 생성 답변의 정확성 검증은 포함하지 않습니다. 검증 화면은 제품 빌드 진입점에 포함되지 않습니다.

## 병합 시 참고

#32를 먼저 검토·병합한 뒤 #31을 이어서 검토하는 순서를 유지합니다. #31에는 통합 확인을 위해 #32 커밋이 포함되어 있으므로, #32가 병합되기 전에는 해당 변경도 #31의 변경 목록에 나타납니다.

특히 Squash 방식으로 #32를 병합하면 커밋 이력이 달라질 수 있으므로, 실제 병합 후 #31에 최신 main을 다시 반영하고 충돌 여부를 확인합니다. 승인·main 병합은 이번 충돌 해결 작업에 포함하지 않았습니다.
