# 오류 제보 UI 현행안

2026-09-18 테스트 화면 기준. 팀 공유 및 후속 연동 검토용이며 운영 반영 완료를 의미하지 않습니다.

## 사용 흐름

답변 오류 제보 → 오류 유형 선택 → 필요한 설명·문구·캡처 추가 → 내용 확인 → 제보

질문과 답변은 자동 연결합니다. 별도 페이지로 이동하지 않고 현재 답변 옆 또는 화면 하단에서 작성합니다.

| 항목 | 최신 시안 | 입력 규칙 |
|---|---|---|
| 오류 유형 | 한 줄 드롭다운 | 필수, 1개 선택 |
| 유형 목록 | 사실과 다른 답변 / 질문과 관련 없는 답변 / 출처·근거가 맞지 않음 / 답변이 이해하기 어려움 / 화면·기능 오류 / 기타 | 기본값은 미선택 |
| 추가 설명 | 기본 ‘선택’, 기타 선택 시 ‘필수’로 변경 | 기타는 공백만 입력하면 불가. 최대 2,000자. 시안에는 최소 10자 제한 없음 |
| 답변 문구 | 본문 드래그 → 선택 문구를 설명에 추가 | 설명의 2,000자 제한에 포함 |
| 캡처 | Win + Shift + S → 범위 선택 → 제보창으로 복귀 → Ctrl + V | 선택 사항, 이미지 1개·5MB 이하, PNG/JPG/WebP |
| 파일 선택 | 캡처 붙여넣기의 대체 방법 | 동일한 이미지 제한 |
| 캡처 미리보기 | 선택 후 표시, 삭제·다른 이미지로 교체 가능 | 현재 시안은 서버 전송 없음 |

일반 텍스트 붙여넣기는 추가 설명 입력에 그대로 사용합니다. 이미지 붙여넣기는 제보 패널이 펼쳐진 동안 처리합니다.
새 이미지를 선택하면 기존 이미지를 대체합니다. 현재 캡처 상태는 패널을 접거나 닫으면 사라지는 시안이므로, 실제 서비스 연결 전에는 작성 중 첨부 유지 또는 제거 안내 정책을 정해야 합니다.

## 화면 배치

```text
답변 오류 제보                    접기  닫기
오류 유형 (필수)
[오류 유형을 선택해 주세요                ▾]
[선택 문구를 설명에 추가]
추가 설명 (선택 / 기타 선택 시 필수)
[                                        ]
캡처 화면 (선택)
Win + Shift + S로 범위 선택 → Ctrl + V
[이미지 파일 선택]  [이미지 미리보기·삭제]
[                제보 보내기              ]
```

상단 접기·닫기는 패널 내부 스크롤 중에도 고정합니다. 모바일에서는 화면 높이의 최대 60%(최대 520px)를 사용합니다.
긴 문구·캡처·키보드가 표시되면 스크롤이 필요할 수 있습니다. 스크롤을 없애기 위해 답변 전체를 가리지 않습니다.

## 시안과 실제 서버 차이

| 구분 | 최신 일반 테스트 시안 | 현재 로컬 서버 연결 |
|---|---|---|
| 오류 유형 | 1개 필수 | 1개 필수 |
| 일반 유형 설명 | 선택 | 모든 유형에 10~2,000자 필요 |
| 기타 설명 | 공백 제외 1자 이상 | 10~2,000자 필요 |
| 선택 문구 | 설명에 포함 | 설명에 포함 |
| 캡처 | 브라우저 미리보기 | 업로드·저장 API 없음 |
| 제출 | 가상 요청 목록에만 기록 | 회원의 실제 제보 저장 |

테스트의 ‘PR #20 오류 제보’ 메뉴는 기존 복수 유형/문구 계약 비교용입니다. 최신 단일 드롭다운 시안과 규칙이 다르며, 해당 메뉴명만으로 PR의 현재 병합 상태를 판단하면 안 됩니다.

## 담당자 협의 및 반영 순서

1. UI 담당: 드롭다운·조건부 필수·문구 선택·캡처 미리보기 확정.
2. 오류 제보 백엔드 담당: 일반 유형 빈 설명 허용, 기타 공백 차단, 최대 길이 규칙을 서버에서도 검증. 기존 클라이언트 호환 확인.
3. 백엔드/저장소 담당: 이미지 전송 방식, 이미지 보관 위치, 제보와의 연결 필드, 실제 파일 유형·용량 검사 결정.
4. 권한 확인: 본인과 관리자만 제보 및 첨부를 조회하도록 기존 비공개 문의 정책과 연결. 공개 이미지 링크로 개인 캡처가 노출되지 않도록 설계.
5. 공동 검증: 이미지 없이 제출 / 기타 빈 설명 차단 / 캡처 첨부 저장·조회 / 전송 실패 시 작성 내용 유지 / 모바일 붙여넣기·키보드 확인.
6. 서버가 준비된 뒤 실제 화면 연결. UI에서 임의 설명을 채워 기존 10자 제한을 우회하지 않음.

현재 테스트에서는 이미지가 제보 payload에 포함되지 않습니다. 캡처를 선택한 채 가상 제출해도 실제 첨부 접수 검증은 아닙니다.

## 확인 상태

- 브라우저 확인: 기타 빈 설명 제출 차단, 일반 유형 설명 생략 허용, 라벨 전환, 드롭다운 선택.
- 기존 실제 화면 확인: 패널 열기·접기·닫기, 본문 드래그 후 설명에 추가.
- 빌드 및 기존 입력 검증 통과.
- 미확인: 실제 Windows 캡처 붙여넣기, 모바일 키보드·기기별 클립보드, 첨부 저장·조회, 실제 오류 제보 제출.
- 8081 Docker에는 이번 시안 변경을 반영하지 않았음.

## V21 원본과 오류 유형 대조

기준 파일: HERITAGE_UI_LAYOUT_PREVIEW_V21_AUTO_HERITAGE_2026-09-18.html. 일반 테스트의 6개 유형과 순서를 원본대로 복원했습니다.
새 유형 코드 irrelevant_answer / unclear_answer / ui_function_error는 시안용 제안이며 운영 API에 전송하지 않습니다. 백엔드 담당자와 유형 값·저장 방식 합의가 필요합니다.
화면·기능 오류에는 화면 깨짐, 버튼 미작동 등을 포함합니다. 로그인 실패·검색 실패처럼 저장된 답변이 없는 상황의 제보는 별도 공통 진입점과 선택적 답변 연결 설계가 필요하며 아직 구현하지 않았습니다.
