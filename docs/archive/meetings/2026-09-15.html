2026.09.15 회의 정리 · 팀 공유용

이번 회의의 중심 방향은 기존 RAG를 새 화면에서 사용할 수 있게 연결하고, 회원별 검색 기록과 비공개 오류 제보까지 먼저 완성한다는 것입니다. 추가 기능은 이 흐름이 안정적으로 동작한 뒤 하나씩 검토합니다.

이 문서는 회의 메모를 바탕으로 정리했습니다. ‘회의 정리’는 전달받은 내용이며, 누락·기억 차이가 있으면 팀원이 보완합니다. ‘제안’은 후속 논의를 위한 내용으로 확정된 배정이나 일정이 아닙니다. 기존 9/14 현황 문서는 보존하고, 역할과 우선순위는 이번 회의 내용을 우선 참고합니다.

1. 이번 회의에서 정리한 방향

구분회의 정리진행 시 의미
먼저 맞출 업무문규님·유진님이 화면과 서버 사이 통신 규칙 및 DB 스키마 정립 진행어떤 정보를 주고받고 어디에 저장할지 먼저 맞춤
최소 MVP기존 3차 RAG가 동작하는 프론트엔드 + 회원 기능과 개인 검색 기록 + 회원별 비공개 오류 게시판사용자가 처음부터 끝까지 사용할 핵심 흐름을 우선 완성
기존 업무3차에서 마무리하지 못한 담당 업무는 각자 이어서 개선기존 전문 분야를 살리되 공통 기능에 영향을 주는 변경은 연결 담당자와 확인
추가 업무Docker 수업 이후 추가 배정배포 담당과 세부 일정을 지금 확정하지 않음
역할 운영기존 역할 분담표는 예시이며 유연하게 대응예시표의 이름만 보고 업무를 고정하지 않음
추가 기능핵심기능 구현 후 여유에 따라 순차 반영추가 기능 때문에 핵심 연결과 검증이 늦어지지 않도록 조절

MVP는 발표와 시연에서 실제로 끝까지 사용할 수 있도록 먼저 완성할 최소 기능 묶음을 뜻합니다.

2. 먼저 완성할 사용자 흐름

01검색
02답변·출처 확인
03내 검색 기록 확인
04해당 답변의 오류 제보
05내 제보 확인

로그인이 필요한 지점과 비회원 검색 허용 여부는 아래 논의 항목에서 정합니다. 공개 자유게시판과 회원별 비공개 문의함은 구분합니다.

기능회의에서 잡은 범위완료 확인 기준 제안아직 맞출 내용
RAG 검색 화면3차 RAG가 프론트엔드에서 동작실제 질문을 보내 답변·출처를 받음. 대기 중·실패 상태도 구분 표시사용할 화면·서버 연결 형식, 비회원 검색 허용 여부
회원 기능회원별 기능 사용 기반가입·로그인·로그아웃이 동작하고 현재 사용자를 구분입력 항목, 로그인 유지 방식
개인 검색 기록회원에게 귀속된 기록 저장로그인 사용자의 기록을 저장하고 본인 기록만 조회질문만 저장할지 답변·출처도 함께 저장할지, 삭제·보관 기간
비공개 오류 제보본인 문의·오류만 확인, 다른 회원의 내용은 비공개등록·목록·상세가 동작하며 타인의 제보를 조회할 수 없음답변과 자동 연결 여부, 제보 유형, 담당자 확인·답변 방식

제안: 오류 제보는 별도 공개 글쓰기로 시작하기보다 답변 아래 ‘오류 제보’ 버튼에서 질문·답변을 연결하면 사용자의 입력과 담당자의 확인 부담을 줄일 수 있습니다. 자동 연결 범위는 통신 규칙·DB 설계 때 함께 정합니다.

3. 비슷한 일을 묶어 진행하는 방법

아래 묶음은 업무 배분을 쉽게 하기 위한 제안입니다. 회의에서 이름이 나온 업무 외의 담당자는 미정으로 둡니다.

작업 묶음함께 설계할 내용담당·연관자먼저 필요한 것
연결 규칙·저장 구조검색 요청·응답, 회원 식별, 검색 기록과 제보의 연결, 오류 응답 형식문규님·유진님 진행. 관련 화면·RAG 담당자 확인실제 기존 RAG 응답 예시
핵심 검색 연결검색창, 수준 선택이 있다면 기존 선택 기능, 답변·출처, 로딩·실패 안내구현 담당은 팀에서 정함. 기존 RAG 담당자 연관요청·응답 예시 합의
회원별 정보 관리회원, 내 검색 기록, 내 제보 목록·상세구현 담당은 팀에서 정함. 화면·서버·DB 연관사용자와 데이터의 연결 방식
기존 RAG 개선각자 미완료 업무, 검색·Prompt·생성 평가, 출처·교정 품질기존 담당자가 이어서 진행. 운영 변경 시 연결 담당자 확인개선 전 기준과 확인 사례
배포·통합 검증Docker 실행, 설정 분리, 실행 절차, 발표 환경Docker 수업 후 추가 배정핵심 기능의 연결 상태

제안: 구현은 묶음별로 나누더라도 ‘누가 최종 연결을 확인하는지’는 각 묶음에 한 명씩 정하면 좋습니다. 이는 팀장을 대신하는 역할이 아니라 담당자 사이 누락을 줄이는 역할입니다.

문규님·유진님이 먼저 맞추면 좋은 최소 항목

  • 검색 요청: 질문과 이용자 수준 등 실제 필요한 입력.
  • 검색 응답: 답변, 출처, 응답 유형, 검색 기록 식별값의 필요 여부.
  • 회원 식별: 서버가 로그인 상태를 확인해 현재 사용자를 결정하는 방식.
  • 저장 관계: 회원 → 검색 기록, 회원 → 오류 제보, 필요하면 오류 제보 → 검색 기록 연결.
  • 실패 응답: 로그인 필요, 권한 없음, 모델 응답 지연 등의 화면 표시 규칙.
  • 변경 공유: 형식을 바꿀 때 함께 수정해야 하는 화면·서버·RAG 담당자.

DB 스키마는 어떤 정보를 어떤 표에 저장하고 표끼리 어떻게 연결할지 정한 설계도입니다. 전체 구조를 완벽히 설계하기보다 핵심 흐름에 필요한 관계부터 맞추는 것을 제안합니다.

4. 회원별 비공개 기능에서 함께 확인할 것

‘다른 회원에게 보이지 않음’은 화면에서 목록을 숨기는 것만으로 끝나지 않습니다. 서버에서도 해당 기록과 제보가 로그인 사용자 본인의 것인지 확인해야 합니다.

확인 상황기대 동작 제안
A회원이 검색·제보 등록A회원에게 귀속되어 저장
B회원으로 로그인A회원 기록·제보가 목록에 표시되지 않음
B회원이 A회원 상세 주소나 번호로 접근서버에서 조회 거부
비로그인 상태에서 개인 기록 접근로그인 안내 또는 접근 거부
제보 처리 담당자가 확인담당자 역할과 허용 범위를 정한 뒤 접근 허용

관리자 페이지 전체 구현은 이번 메모에서 확정된 내용이 아닙니다. 다만 제보를 누가 확인하고 어떻게 처리할지는 필요합니다. 최소 담당자 조회 기능을 둘지, 기존 관리 기능을 활용할지 먼저 합의하면 좋겠습니다.

5. 핵심 기능부터 완성하는 일정안

아래 날짜는 제안입니다. 기존 문서의 9/23 발표 예정일을 가정했으며, 공식 일정과 Docker 수업 날짜에 따라 조정합니다. 주말 작업을 기본 전제로 두지 않습니다. 현재 구현 완료율은 확인되지 않아 %로 표시하지 않았습니다.

날짜핵심 목표연결·회원 기능기존 업무·품질 개선하루 완료 기준 제안
9/16 수연결 약속 맞추기문규님·유진님 중심으로 통신 예시·DB 관계 정리. 구현 담당 확인각자 개선할 항목과 공통 영향 정리입력·출력 예시와 최소 저장 관계 공유
9/17 목실제 RAG 연결화면 → 서버 → 기존 RAG → 답변·출처 연결. 회원 기능 연결 병행핵심 연결을 막는 문제 우선 지원로그인 기능과 실제 검색 경로 각각 확인
9/18 금회원별 흐름 통합개인 검색 기록·오류 제보의 등록·조회 연결확정된 소규모 개선만 통합가입부터 검색·내 기록·내 제보까지 한 번에 시연
9/19~20 주말여유 구간정규 배정 없음추가 작업은 팀 합의 시에만미완료 작업의 새 담당·기한을 평일 기준으로 정리
9/21 월통합·권한·배포 확인타인 정보 접근 차단, 로그인 만료, 오류 안내 확인. 수업 후 배정에 따라 배포 검증개선 전후 결과와 남은 한계 정리핵심 기능의 필수 오류 해결, 추가 기능 착수 여부 결정
9/22 화발표 안정화실행 버전 고정, 리허설, 시연 대체 자료 준비실제 구현·실험·미반영 제안을 구분발표 시나리오가 끝까지 동작
9/23 수 예정발표·제출최종 접속 확인성과와 한계 설명일정은 공식 안내 재확인

Docker 작업은 위 날짜만으로 확정하지 않습니다. 수업 후 담당과 실행 환경을 정하고, 9/21 검증 전에 준비 가능한지 확인합니다.

지연 시 제안: 먼저 추가 기능을 보류하고 핵심 연결을 함께 해결합니다. 발표를 위해 타인 데이터 접근 제한이나 오류 처리를 생략하지 않습니다. 일정상 MVP 일부도 어렵다면 팀에서 범위·기한을 명시적으로 다시 정합니다.

6. 추가 기능은 언제 검토할까?

묶음후보 기능착수 전 조건 제안
검색 결과 탐색사진·상세 화면, 문화유산 설명 페이지기존 답변·출처 흐름 완료, 데이터 연결 방식 확인
첫 화면 콘텐츠오늘의 소식·인기 키워드집계·선정 기준과 데이터 공급 방법 합의
개인 사용 편의검색 기록 삭제·필터·이전 답변 비교기본 회원별 기록 저장·조회와 접근 제한 완료
제보 처리 편의처리 상태·관리자 답변·알림기본 비공개 제보와 담당자 처리 방식 확정

회원별 개인 검색 기록의 기본 저장·조회는 이번 MVP입니다. 이전 제안 문서에서 선택 기능이었다고 해서 추가 기능으로 미루지 않습니다. LangChain 검토 같은 기존 업무 개선은 별도 실험으로 이어갈 수 있지만 운영 반영이 MVP 연결을 지연시키지 않도록 관련 담당자와 조율합니다.

추가 기능 착수 기준 제안: 핵심 사용자 흐름이 동작하고, 타인 기록·제보 접근이 차단되며, 남은 시간 안에 구현과 검증을 함께 끝낼 수 있는 항목 한 개부터 선택합니다.

7. 다음에 짧게 확인하면 되는 항목

  • 이 회의 정리에서 누락되거나 다르게 기억하는 내용이 있는지.
