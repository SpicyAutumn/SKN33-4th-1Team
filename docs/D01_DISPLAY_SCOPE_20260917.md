# 정정 답변 표시: 기존 화면과 새 화면의 적용 범위

## 결론

PR #6은 **기존 Streamlit 정정 카드**의 개선이다. 병합해도 React 화면에는 자동 적용되지 않는다. 이번 보완은 적용 범위를 명확히 하고 기존 표시 동작을 테스트하는 작업이며, React 구현이나 PR #5 코드를 포함하지 않는다.

확인 기준: PR #6 최초 구현 `3b76de4`, PR #12 병합 `15c7706`, PR #13까지 반영한 main `468cb7f`. 최신 main을 PR #6 브랜치에 병합해 확인했다. 기존 브라우저 확인은 Streamlit 기준이며 React 실행 확인으로 간주하지 않는다.

## 같은 ‘요약’이라도 사용하는 값이 다름

| 항목 | PR #6: Streamlit | 현재 main: React |
|---|---|---|
| 코드 | `app/components/response_cards.py` | `frontend/src/App.jsx` |
| 요약에 쓰는 값 | `premise_correction.corrected_premise` — 바로잡은 전제 | `summary` — 답변 전체의 핵심 요약 |
| 전체 설명 | `message` | `message` |
| 두 문구가 완전히 같음 | 한 번 표시·낭독 | 두 영역에 반복 표시 |
| 요약 없음 | 전체 설명 한 번 표시 | 요약 영역도 `message`로 대체하여 본문과 반복 가능 |
| 긴 설명 | 전체 표시 | 코드상 자르기·접기 없음; 브라우저 실측은 미실시 |
| 음성 | 기존 브라우저 음성 함수 사용 | 해당 답변 컴포넌트에서 음성 기능 확인되지 않음 |

예를 들어 새 `summary`가 추가되어도 기존 Streamlit 카드는 정정 상세와 본문을 사용한다. 이를 새 요약으로 교체하는 것은 별도의 표시 정책 변경이므로 이번에는 하지 않는다.

## 연결 경로: 이전 설명에서 달라진 점

```text
React → POST /api/v1/searches → Django → rag_runtime.answer
      → retrieval.answer → 기존 RAG 처리

Streamlit → 기존 응답 카드(PR #6 적용 대상)
```

근거: `frontend/src/App.jsx`, `backend/api/urls.py`, `backend/api/views.py`, `backend/api/rag_runtime.py`.

PR 본문의 PR #8 화면 설명과 당시 연결 범위 문서의 `/api/ask` 미확정 설명은 과거 확인 기록이다. 현재 main에는 위 경로가 구현되어 있다. 이는 코드 확인 결과이며 실제 서버 요청 성공·DB 저장·배포 확인을 뜻하지 않는다.

## 지금 확인한 것과 남은 것

| 단계 | 상태 / 완료 기준 |
|---|---|
| 기존 Streamlit 표시 | 기존 8개 + 새 summary 호환 3개, 외부 호출 없는 테스트 |
| 새 필드 추가 시 기존 동작 | 정정 상세 우선 유지, 상세 없으면 본문, 동일 문구 한 번, 입력 보존 확인 |
| PR #5와 연결 | PR #5 검토 결과 확정 후 정정 처리된 응답을 카드에 전달해 표시·낭독 문자열 확인 필요 |
| React 최소 보완 | 요약·본문의 완전 중복 방지 및 요약 누락 대체 중복을 별도 변경안으로 제시할 예정 |
| React 음성 | 기존 Streamlit 승인·시험과 구분. MVP 포함 여부와 구현 범위를 별도로 확인해야 함 |
| 실제 서비스 | 최종 코드 기준 브라우저 표시와 실제 API 연결을 별도 확인해야 함 |

PR #5는 생성 결과의 문구를 정리하고, PR #6은 받은 문구를 표시한다. PR #6에서 문구의 사실 여부를 판정하거나 다시 작성하지 않는다. PR #5 병합은 현재 문서·표시 테스트의 선행 조건은 아니지만, 최종 통합 확인에는 확정된 PR #5 결과가 필요하다.

## 업무별 검토 요청

- **기존 화면 유지보수:** 정정 상세와 전체 설명을 함께 보여주는 현재 범위가 적절한지 확인.
- **React 화면:** 현재 핵심 요약 필드는 유지하면서 완전히 같은 요약·본문을 한 번만 표시하는 별도 변경안의 범위를 확인. 음성 추가는 이 PR의 완료 조건으로 취급하지 않음.
- **답변 생성·서비스 연동:** PR #5 확정 후 실제 응답의 `summary`, `message`, 정정 상세 값이 각 화면에서 의도대로 사용되는지 확인.

이번 보완에서는 Prompt, 모델, 응답 형식, React 화면, DB를 변경하지 않는다. 기존 PR 본문·검토 기록은 보존하고 추가 댓글로 현재 범위를 안내한다.
