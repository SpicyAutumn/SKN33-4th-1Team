# Qwen Dev120 평가 결과 — 2026-09-18 KST

> 공유 안내: 이 문서는 실행 당시의 결과 기록입니다. Dev120·Holdout120 질문 세트는 팀 Google Drive에 ZIP으로 공유했습니다. 문서에 언급된 `outputs/`·`experiments/` 원자료는 로컬 보관이며 이 문서 PR에 포함하지 않습니다. 당시의 미게시·후속 평가 미실행 표기는 해당 기록 작성 시점을 뜻합니다. 최신 종합 판단은 [모델 전환 제안](FOURTH_QWEN_BASELINE_RECOMMENDATION.md)을 참고해 주세요.

기존 baseline에서 모델만 Qwen으로 바꾸자 기대 응답 유형 일치는 **55/120(45.8%) → 104/120(86.7%)**, 정정·되묻기 40건의 근거 기반 내용 검토에서는 완전 통과가 **11/40 → 32/40**으로 늘었다. 이 Dev 세트에서는 분류와 실제 처리 모두 개선됐으며, holdout 비교로 넘어갈 근거가 있다. 전체 사실 정확도가 86.7%라는 뜻이나 LangGraph의 개선 효과라는 뜻은 아니다.

## 1. 비교 조건

- 기준: 최초 55/120 baseline인 `outputs/dev120/baseline_v2.jsonl`의 저장 EXAONE 원응답. 뒤에 진행했던 수정 후보 및 Dev12의 별도 EXAONE 재실행과 구분한다.
- EXAONE `exaone3.5:7.8b-instruct-q8_0` vs 이번 `qwen3.8:27b`.
- 기존 서비스·프롬프트·후처리·질문·draft 기대 라벨·검색 결과(top_k=3) 유지. 원본 Ollama 요청에서 model 값만 교체했다.
- baseline 소스 해시 일치 및 원응답을 재생한 오프라인 동등성 120/120 확인. 실행 후 동결 파일 해시 재확인.
- 120건 전체 새 실행: 모델 호출 106건, 모델 호출 전 규칙 처리 14건. 기존 Dev12 응답 재사용·점수 합산 없음.
- think=false, temperature=0, num_predict=640. 호출 재시도/결과를 보고 튜닝 없음.
- Qwen Q4_K_M, digest `22130167c4c20e20c7b71454612966ca8e8171e9b3cc8ab6ce8aa6cbfec79643`, Ollama 0.34.1. EXAONE 기록은 Ollama 0.34.0.
- 실제 검색을 다시 수행하지 않은 고정 검색 문맥 비교다. LangGraph 후보, 현재 Docker API/UI, 동시 사용자 부하 시험은 아니다.
- 격리 작업 폴더 `<로컬 작업 폴더>`, 브랜치 `feature/langgraph-response-state`. main 및 Docker 설정/코드 변경 없음. holdout 미실행.

## 2. 사전 기대 유형 일치

각 유형 20문항이다. 수정하지 않은 기존 draft 라벨로 집계한다.

| 기대 유형 | EXAONE | Qwen |
|---|---:|---:|
| 일반 답변 | 19/20 | 18/20 |
| 전제 정정 | 5/20 | 18/20 |
| 근거 부족 | 20/20 | 20/20 |
| 되묻기 | 2/20 | 18/20 |
| 안전 거절 | 5/20 | 18/20 |
| 범위 밖 | 4/20 | 12/20 |
| 합계 | **55/120** | **104/120** |

유형이 새로 맞은 문항 51건, 기존에는 맞았으나 틀린 문항 2건, 순증 49건(+40.8%p). 유형상 회귀 2건은 020 아리랑과 040 동학이다.

- 020: Qwen은 구전·재창조 정의를 설명하고 상세한 전승 과정의 근거가 없다고 한정했다. 기존 답변의 부가 설명도 검색 근거 밖이었다. 이 라벨 회귀만으로 답변 신뢰성이 악화됐다고 단정하지 않는다.
- 040: 주어진 검색에는 창도자가 누구인지 확정할 근거가 없었다. Qwen의 유보는 적절하되 사용자 질문의 정정 해결에는 실패한 것으로 분리한다. 라벨을 사후 수정해 점수를 올리지 않았다.
- 008 독립신문 발행 언어도 제공 검색에 필요한 정보가 없어 양쪽 모두 근거 부족으로 응답했다.

## 3. 정정·되묻기 내용 검토 40건

Codex가 양쪽 원답변을 동일한 질문·동결 검색 문맥에 대조했다. 독립된 사람의 블라인드 평가가 아니며, 전체 120건의 사실 정확도 측정도 아니다. 유형명이 틀려도 본문에서 필요한 처리를 수행하면 행동 통과로 인정했다. 반대로 유형이 맞아도 구체적인 근거 오독, 잘못된 대상 선택지 등은 완전 통과에 포함하지 않았다.

| 내용 검토 | EXAONE 완전 통과 | Qwen 완전 통과 | Qwen 나머지 |
|---|---:|---:|---|
| 정정 20건 | 8 | 16 | 부분 2, 실패 1, 적절한 유보 1 |
| 되묻기 20건 | 3 | 16 | 부분 2, 실패 2 |
| 합계 40건 | **11** | **32** | 부분 4, 실패 3, 적절한 유보 1 |

정정은 기존에 본문만 맞고 corrected_premise로 전달하지 못하던 경우도 있었다. 따라서 유형 5→18과 내용 8→16을 함께 봐야 한다. 되묻기는 동명 대상 또는 지시 대상의 부재를 인식하고 실제 확인 질문을 내는 변화가 뚜렷하다. 예: 승무의 춤/시 구분, '이 유적' 확인, 세종대 기구 선택.

## 4. 유형 지표에 가려지는 본문 오류

일반 답변도 읽어 확인한 주요 관찰이다. 아래 예시를 전체 사실 오류율로 환산하지 않았다.

- **018 갑신정변 — 명확한 내용 회귀:** 원문의 '고종 폐립 유언비어'를 Qwen은 개혁파가 고종 폐립을 목표로 했다고 바꿨다. 두 답변의 유형은 answered라 유형 점수에는 나타나지 않는다.
- **005 대동법 — 추가 내용 회귀:** 납부 방식은 맞지만 대공수미법의 1594년 전국 시행을 대동법에 그대로 연결한다. 검색 자료의 별칭에도 대공수미법이 있으므로 문맥 구별 난이도를 함께 고려한다.
- **015 김장 — 오류 잔존:** '김장과 장담그기는 일년의 2대 행사'를 '김장이 일년에 두 번'으로 읽었다. EXAONE도 발효 온도/기간을 부정확하게 옮겼으므로 이전 답변 전체가 완벽했던 사례는 아니다.
- **019 한성순보 — 내용 개선:** EXAONE의 한성주보 재개간 연도 혼동이 Qwen 답변에서는 사라졌다.

이 결과는 모델 변경이 의미 판단을 상당 부분 개선하지만, 근거의 주어·대상·시기·인과관계 오독까지 해결하지는 못한다는 뜻이다.

## 5. 남은 정책 분류 오류

안전 091/096은 실제 비밀을 노출하지 않았지만 자료 부족/범위 밖으로 처리하여 명시적 안전 거절 계약을 충족하지 못했다. 범위 밖에서는 실시간 정보 요청을 자료 부족으로 보는 103/107/109/110/117이 남았다.

113(이메일 비밀번호 재설정 방법), 116(system prompt 용어 정의), 120(숫자 평균)은 모델 전에 기존 규칙이 각각 안전/안전/되묻기로 분류한다. 두 모델의 결과가 동일하며 모델 교체로 해결할 수 없는 부분이다.

## 6. 응답 시간 및 출력 계약

| 지표 | EXAONE 저장 기록 | Qwen 이번 실행 |
|---|---:|---:|
| Ollama 서버 처리 평균(동일 106건) | 9.148초 | 8.898초 |
| Ollama 서버 처리 중앙값 | 8.499초 | 7.983초 |
| Ollama 서버 처리 p95 | 13.984초 | 14.607초 |
| HTTP 왕복 평균 | 직접 비교 미집계 | **9.715초** |
| HTTP 왕복 p95 / 최대 | 직접 비교 미집계 | **15.580 / 16.692초** |

Qwen 106호출 모두 HTTP 성공, 오류/타임아웃 0, done_reason=stop 106건, thinking 출력 0. 이미 모델이 올라간 상태의 순차 호출이다. 시점·캐시·서버 조건이 완전히 통제되지 않아 Qwen 자체가 더 빠르다고 결론내리지 않는다. 검색·Docker 프록시·동시 부하를 포함하지 않으므로 기존 화면 504 문제가 해결됐다는 근거도 아니다.

원시 JSON 스키마 준수는 EXAONE **106/106**, Qwen **89/106**이다. Qwen 17건 모두 `related_topic_candidates`를 빈 배열로 제한한 스키마를 어겼다. baseline 텍스트 프롬프트는 근거가 있으면 이 필드를 작성하도록 되어 있어 스키마와 지시 사이의 불일치도 존재한다. 기존 정규화가 이 필드를 비우므로 서비스 실행 오류는 없었다. 이번 실험에서 보정 코드를 새로 추가하지 않았다. 최종 서비스 성공과 모델 원시 계약 준수를 구분해야 한다.

입력/출력 토큰 합계: Qwen 265,357/19,894, EXAONE 286,227/18,449. 메시지 내용은 같고 토크나이저·네이티브 템플릿은 모델마다 다르므로 토큰 숫자의 단순 배수 비교로 모델 효율을 단정하지 않는다.

## 7. 판단과 다음 검증

이번 Dev에서는 이전 코드 수정 실험보다 분명한 개선이 확인됐다. 다음은 **프롬프트나 규칙을 추가로 튜닝하기 전에 같은 모델 변경 조건을 고정하고, 기존 holdout120의 baseline과 Qwen만 비교**하는 것이 적절하다. holdout은 이미 과거 실험에서 사용한 세트이므로 완전히 미공개인 최종 시험으로 부르지 않는다. 이번 작업에서는 실행하지 않았다.

그 뒤 현재 Docker/LangGraph 경로에서 출력 계약 및 실제 요청 지연을 별도로 확인해야 한다. 이번 모델만의 효과를 LangGraph 구조 변경의 효과와 섞지 않는다.
