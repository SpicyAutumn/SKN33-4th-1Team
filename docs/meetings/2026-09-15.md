## 1. 회의 정리

**기존 RAG를 새 화면에 연결하고, 회원별 검색 기록과 비공개 오류 제보까지 먼저 완성합니다.**

| 항목 | 전달받은 회의 내용 |
|---|---|
| 연결 규칙·DB 구조 | 문규님·유진님이 화면과 서버 사이 통신 규칙 및 DB 스키마 정립 진행 |
| 최소 기능(MVP) | 기존 3차 RAG가 동작하는 화면, 회원 기능과 개인 검색 기록, 회원별 비공개 오류 게시판 |
| 기존 업무 | 3차에서 마무리하지 못한 담당 업무는 각자 이어서 개선 |
| 추가 배정 | Docker 수업 이후 진행. 배포 담당·세부 일정은 아직 확정하지 않음 |
| 역할 운영 | 기존 역할 분담표는 예시이며 유연하게 대응 |
| 추가 기능 | 핵심 기능 구현 후 여유에 따라 순차 반영 |

## 2. 우선 완성할 사용자 흐름

검색 → 답변·출처 확인 → 내 검색 기록 확인 → 해당 답변의 오류 제보 → 내 제보 확인

| 기능 | 완료 확인 기준 제안 | 아직 맞출 내용 |
|---|---|---|
| 검색 화면 | 실제 질문에 답변·출처 반환, 대기·실패 구분 | 화면·서버 연결 형식, 비회원 검색 허용 |
| 회원 기능 | 가입·로그인·로그아웃, 현재 사용자 구분 | 입력 항목, 로그인 유지 |
| 개인 검색 기록 | 본인에게 귀속하여 저장하고 본인 기록만 조회 | 질문 외 답변·출처 저장 여부, 삭제·보관 기간 |
| 비공개 오류 제보 | 등록·목록·상세, 타인 제보 조회 차단 | 답변 자동 연결, 유형, 담당자 처리 방식 |

답변 아래 오류 제보 버튼에서 질문·답변을 연결하는 방식은 **제안**입니다. 공개 자유게시판과 회원별 비공개 문의함을 구분합니다.

## 3. 연결·역할 조율

문규님·유진님이 진행하는 연결 규칙·저장 구조 외에, 핵심 검색 연결·회원별 정보 관리·배포 및 통합 검증의 세부 구현 담당은 팀에서 정합니다. 기존 RAG 개선은 기존 담당자가 이어가되 공통 기능에 영향을 주면 연결 담당자와 확인합니다.

먼저 맞출 최소 항목:

- 질문·이용자 수준 등 검색 요청 입력과 답변·출처·응답 유형 등 출력 예시.
- 검색 기록 식별값의 필요 여부와 회원 → 기록/제보, 제보 → 기록의 연결 관계.
- 서버가 로그인 사용자를 확인하는 방식.
- 로그인 필요·권한 없음·모델 지연 등 실패 응답 표시.
- 형식 변경 시 함께 수정할 담당자.

작업 묶음별 최종 연결 확인자를 한 명씩 정하는 것은 누락 방지를 위한 **제안**이며 확정 배정이 아닙니다.

## 4. 비공개 기능의 확인 항목

목록을 숨기는 것뿐 아니라 서버에서도 본인 소유 여부를 확인해야 합니다.

| 상황 | 기대 동작 제안 |
|---|---|
| A회원 등록 | A회원 소유로 저장 |
| B회원 로그인 | A회원 기록·제보를 목록에 표시하지 않음 |
| B회원이 A회원 상세 번호로 접근 | 서버에서 조회 거부 |
| 비로그인 개인 기록 접근 | 로그인 안내 또는 접근 거부 |
| 처리 담당자 조회 | 담당자 역할과 허용 범위를 합의한 뒤 허용 |

관리자 페이지 전체 구현은 확정되지 않았습니다. 제보 확인·처리 담당과 최소 처리 방식은 정해야 합니다.

## 6. 추가 기능 — 핵심 흐름 완료 후 검토

- 사진·상세 화면·문화유산 설명 페이지: 기존 답변·출처 흐름과 데이터 연결 확인 후.
- 오늘의 소식·인기 키워드: 선정·집계 기준과 공급 방법 합의 후.
- 기록 삭제·필터·이전 답변 비교: 기본 저장·조회와 접근 제한 완료 후.
