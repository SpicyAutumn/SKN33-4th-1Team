# 인물 호칭에 따른 동명이인 구분

2026-09-18, `fix/entity-query-resolution`의 인물명 검색 수정에 대한 후속 보완.

## 원인과 수정

앞선 수정본에서 `세종`과 `세종 대왕` 모두 조선 왕과 신라 장군을 선택지로 제시했다.
호칭이 있어도 메타데이터의 '인물' 유형까지만 구분했기 때문이다.

`src/rag_indexing/entity_matching.py`에서 이름과 결합한 호칭을 문서의 정의와 대조한다.
`대왕`은 왕·군주 계열, `장군`은 장군·장수·무신 계열로 연결한다. 문서의
`definition` 청크가 끝부분에서 명시하는 직위·직업을 사용한다. 긴 본문의 다른
인물 언급이나 '왕을 보좌한 신하'를 왕의 근거로 사용하지 않는다.

같은 제목의 후보 중 요청한 직위가 확인되면 다른 직위로 정의된 동명이인을
제외한다. 직위를 알 수 없는 후보와 같은 직위의 여러 후보는 유지한다.
호칭까지 일치하는 인물은 '장군' 같은 일반 명사 제목보다 먼저 배치한다.
특정 인물명이나 문서 ID는 운영 규칙에 하드코딩하지 않는다.

적용 대상은 이름+호칭 형태의 짧은 검색 및 일부 소개 요청이다.
`세종대왕`처럼 붙인 형태도 인식한다. 이름만 입력하거나 비교·부정·복잡한
질문을 했을 때 이 새 규칙으로 대상을 확정하지 않는다. 모든 자유로운 문장의
의미를 판별하는 기능은 아니며 정의 문장의 표현이 달라지면 구분하지 못할 수 있다.

모델, 시스템 프롬프트, top_k=3, 검색 가중치는 유지했다. 추가 모델 호출은 없다.
main 및 이전 실험 기록은 변경하지 않았다.

## 검증

회귀 테스트: **188 passed, 180 subtests passed**.
기존 검색·서비스·생성기 테스트에 왕/장군 구분, 다른 이름에도 같은 규칙 적용,
비교·부정 보존, 알 수 없는 직위 보존, 본문의 왕 언급 무시, 일반 명사보다
호칭이 붙은 인물 우선 등의 검증을 추가했다.

로컬 원기록:

- 수정 전 실제 API: `_local/live_checks/sejong-live-http.jsonl`
- 첫 후보: `_local/live_checks/sejong-role-candidate.jsonl`
- 순위 보완 후 후보: `_local/live_checks/sejong-role-candidate-v2.jsonl`

첫 후보는 `세종 대왕`과 `세종대왕`에 조선 왕으로 답변했다. 그러나
`세종 장군`은 신라 인물 문서를 찾고도 모델이 근거 부족으로 응답했다.
당시 일반 명사 '장군'이 먼저 전달되는 문제도 확인해 인물의 순위를 보완했다.
두 번째 후보에서는 신라 인물을 1위에 배치하고 조선 왕은 제외했지만,
모델이 여전히 시대를 묻는 needs_clarification을 반환했다. 순위만으로 해결되지
않은 생성 단계의 한계이며 5건 전부 성공했다고 집계하지 않는다.
이 실패 기록도 보존한다. 답변 유형 성공이 답변의 모든 문장에 대한 사실 검증을
의미하지는 않으며 전체 Dev/holdout 성능 개선을 주장하지 않는다.
