**현재 실험한 LangChain·LangGraph 구성을 Qwen baseline보다 우수한 품질 개선안으로 채택할 근거는 확보하지 못했다.** LangChain의 일반 답변에서 근거 충실도 개선 신호는 있지만 전체 선정40문항의 개선은 불확실하다. LangGraph의 근거 충실도는 하락했다. 다만 일부 하락은 평가 모델이 근거 부족 안내를 잘못 해석한 영향도 있어 점수 감소 전체를 실제 품질 저하로 단정하지 않는다.

## 범위와 평가 조건

- 기존 Dev120 실행별 저장 결과 중 **동일한 일반 답변 기대20 + 정정 기대20 = 40문항**을 전부 선정했다. LangChain40·LangGraph40, 신규80개 응답을 채점했다. Qwen baseline40 점수는 이전 사후 평가 결과를 재사용했다.
- 이 결과는 **각 Dev120 전체의 RAGAS 점수가 아니다.** 나머지 되묻기·근거 부족·안전·범위 유형80문항은 이 비교의 평균에 포함하지 않았다. LangChain·LangGraph holdout은 평가하지 않았다.
- 각 실행의 최종 `response.message`를 사용했다. 바깥 공백만 제거했으며, Graph 메시지에는 정정 문구와 본문이 이미 포함되어 있다. 별도의 원시 초안이나 정정 필드를 추가하지 않았다.
- Faithfulness에는 실제 제공 문서의 **제목+본문**을 넣었다. baseline/Graph는 원래3개, Chain은 원래3개를 유지하고 인접 본문을 보충한4~6개다. Chain 점수 변화는 늘어난 검색 문맥을 포함한 시스템 효과이며 라이브러리 자체의 효과가 아니다.
- 공식 RAGAS **0.4.3**의 Faithfulness와 AnswerRelevancy 기본 프롬프트·수식을 사용했다. 평가 모델 `gpt-4.1-mini-2025-04-14`, 임베딩 `text-embedding-3-small`, temperature0, max_tokens4096, AnswerRelevancy strictness3.
- 저장소의 한국어 역질문 유도 문구는 적용하지 않았다. 호환성 shim만 재사용했다. 설치된 공식 지표 파일4개는 앞서 확인한 공식 소스 해시와 다시 대조했다.
- baseline Faithfulness는 이전 제목+본문 민감도 평가, AnswerRelevancy는 이전 원평가 캐시다. baseline을 새로 채점하지 않아 호출 시점과 평가 모델의 변동성은 통제하지 못했다. 새 후보의 문장 추출도 새로 수행했으므로 제목 유무만 비교하는 실험과는 다르다.
- 사용자에게 추가80개 답변·질문·문맥의 OpenAI API 전송 및 비용 사용에 대한 명시적 동의를 받은 뒤 실행했다. 답변 생성 모델과 검색은 다시 호출하지 않았다. 운영 코드·Docker·환경 설정은 변경하지 않았다.

## 결과

점수는0~1 범위이며 정답률이나 유형 일치율이 아니다.

| 대상 | 지표 | Qwen baseline | LangChain + 본문 보충 | LangGraph 2단계 |
|---|---|---:|---:|---:|
| 선정 전체40 | Faithfulness | 0.9203 | 0.9373 | 0.8504 |
| 선정 전체40 | AnswerRelevancy | 0.3380 | 0.3510 | 0.3212 |
| 일반 답변 기대20 | Faithfulness | 0.8812 | 0.9534 | 0.8722 |
| 일반 답변 기대20 | AnswerRelevancy | 0.3339 | 0.3746 | 0.3269 |
| 정정 기대20 | Faithfulness | 0.9594 | 0.9211 | 0.8286 |
| 정정 기대20 | AnswerRelevancy | 0.3420 | 0.3273 | 0.3155 |

선정40문항의 문항별 차이를 10,000회 paired bootstrap으로 집계했다(seed20260918). 여러 지표·부분집합을 함께 살핀 탐색적 분석이며 다중 비교 보정은 하지 않았다. 신뢰구간은 문항 표본 변동을 나타내며 평가자의 반복 채점 변동까지 포함하지 않는다.

| 비교 | 지표 | baseline 대비 차이 | 95% 구간 | 상승/하락/동점 문항 |
|---|---|---:|---|---:|
| LangChain + 본문 보충 | faithfulness | +0.0170 | [-0.0425, +0.0759] | 12/6/22 |
| LangChain + 본문 보충 | answer_relevancy | +0.0130 | [-0.0243, +0.0539] | 18/18/4 |
| LangGraph 2단계 | faithfulness | -0.0699 | [-0.1395, -0.0058] | 8/16/16 |
| LangGraph 2단계 | answer_relevancy | -0.0167 | [-0.0416, +0.0043] | 14/21/5 |

LangChain 일반 답변20의 Faithfulness 차이는 +0.0723, 구간 [+0.0041, +0.1594]로 개선 신호가 있다. 정정20에서는 -0.0383이고, 전체40에서는 두 지표 모두 차이 구간이0을 포함한다. **일반 답변의 문맥 보충 효과는 관찰됐지만 정정·되묻기의 의미 판단 개선을 입증한 것은 아니다.**

LangGraph 정정20의 Faithfulness는0.9594→0.8286, 차이 -0.1309, 구간 [-0.2376, -0.0422]다. 전체40에서도 하락 구간이0 미만이다. 이 하락에는 근거 없는 정정과 잘못된 근거 부족 안내, 평가자의 문맥 오독이 함께 섞여 있다.

## 근거 부족 응답과 평가 언어의 영향

선정40개 중 실제 근거 부족 상태는 baseline4, Chain2, Graph7건이다. 기대 라벨로 선정했기 때문에 이 응답들도 주 분석에서 빼지 않았다. Graph의 `answered`33건에는 정정이 있는15건이 포함된다. 정정 여부를 별도 축으로 표현하는 계약이므로 raw `answered`를 일반 답변33건으로 읽으면 안 된다.

양쪽 모두 답변을 제공한 상태인 문항만 남기는 조건부 민감도 분석은 아래와 같다. 출력 상태로 조건을 걸기 때문에 주 분석을 대체하거나 성공한 사례만으로 전체 성능을 주장하는 데 사용하지 않는다. Graph에서는 근거 부족과 정정을 함께 수행한 응답도 이 분석에서 빠진다.

| 비교 | 남은 문항 | Faithfulness baseline→후보 | AnswerRelevancy baseline→후보 |
|---|---:|---:|---:|
| Chain | 36 | 0.9300→0.9488 | 0.3755→0.3664 |
| Graph | 33 | 0.9236→0.9030 | 0.3793→0.3780 |

이 조건부 분석에서는 두 후보의 두 지표 모두 차이 구간이0을 포함한다. 응답 유보 비율과 그 문구에 대한 평가가 전체 점수 차이에 영향을 준다는 뜻이다.

공식 AnswerRelevancy 역질문120개씩에서 한글 없이 라틴 문자가 나타난 것은 baseline112, Chain108, Graph109개였다. 한국어 원질문과 다른 언어의 역질문을 임베딩으로 비교한 영향이 있어 약0.3대의 절대 점수를 그대로 서비스 품질 등급으로 해석하면 안 된다. 유보(noncommittal) 판정도 점수에 영향을 준다. 공식 프롬프트 유지와 이전 비교의 일관성을 위해 결과를 본 뒤 한국어 프롬프트로 재채점하지 않았다.

## 기존 실행 비용과 함께 해석

아래는 이전 Dev120 답변 생성 기록이며 **이번 사후 평가 API 비용과 구분**한다.

| 항목 | Qwen baseline | Chain + 본문 보충 | Graph 2단계 |
|---|---:|---:|---:|
| 생성 모델 호출 | 106 | 106 | 142 |
| 입력 토큰 | 265,357 | 449,099 | 273,672 |
| 출력 토큰 | 19,894 | 22,307 | 13,693 |
| 120건 평균 HTTP 시간(무호출0 포함) | 8.582초 | 11.210초 | 8.285초 |
| 정정·되묻기40 내용 완전 통과(기존 잠정 검토) | 32 | 31 | 31 |

Graph 전체 평균 시간은 짧지만 분기 구성이 달라서다. 동일한2회 호출33문항에서는11.355→16.696초였고 전체 p95도14.762→19.182초로 늘었다. 일반적인 속도 향상으로 주장하지 않는다. 내용 검토32→31도 작은 차이와 경계 판정이 있으므로 확정적 성능 저하로 단정하지 않는다.

답변 생성은 Runpod–Ollama의 같은 로컬 모델 태그 `qwen3.8:27b`, Q4_K_M, think=false, temperature0과 저장 검색 결과를 사용했다. A40은 사용자 제공 환경 정보다. 모델·세부 생성 설정·본문 보충·Graph 계약 차이는 기존 Dev120 보고서를 따른다. 현재 Docker/프런트의 최신 통신 규약이나 실시간 검색·동시 부하를 평가한 결과는 아니다.

**권고:** Qwen baseline을 다음 개선의 기준으로 유지한다. Chain의 근거 보충은 일반 답변 개선 아이디어로 남길 수 있으나 입력 토큰 약69% 증가와 정정 개선 미확인을 함께 제시한다. 현재 Graph2단계는 호출 수 증가를 정당화할 품질 개선을 보여주지 못했다. 이 결론은 이번 구현·문항·조건에 한정하며 LangChain/LangGraph 일반의 가능성을 부정하지 않는다.
