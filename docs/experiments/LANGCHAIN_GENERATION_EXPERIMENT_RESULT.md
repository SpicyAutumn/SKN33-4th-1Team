# LangChain 생성 연결 실험 결과 — 운영 미적용

2026-09-18 정리. 이 문서는 참고용 실험 기록이며 서비스 실행 안내가 아니다.

## 목적과 결론

모델 호출을 LangChain으로 연결해도 기존 입력·출력과 출처 복원·정정 후처리를 유지할 수 있는지 확인했다. 제한된 사례에서 연결 가능성을 확인했지만 **답변 품질 향상이나 운영 도입의 타당성을 입증하지는 않았다.** 현재 서비스에 LangChain을 연결하지 않는다.

최종 저장소에서 서비스 실행에 필요한 코드와 참고 자료가 혼동되지 않도록, PR #9는 실험 코드·전용 테스트·의존성 대신 이 결과 문서만 남긴다. 이는 실험 결과의 폐기가 아니라 보관 방식 변경이다.

## 무엇을 비교했는가

| 방식 | 처리 흐름 |
|---|---|
| 기존 | 기존 요청 준비 → Ollama 호출 → 기존 응답 해석·후처리 |
| 실험 | 기존 요청 준비 → ChatPromptTemplate → ChatOllama → 응답 형식 변환 → 기존 응답 해석·후처리 |

실험은 기존 생성기의 모델 호출 부분만 교체했다. 프롬프트 작성과 후처리를 모두 LangChain으로 다시 구현한 것은 아니다.

## 한계와 미확인 사항

- 두 방식 모두 근거 밖 역할·방문객 설명이 남았다. 답변 정확성 개선을 입증하지 않았다.
- 원응답에 있던 근거 없는 선택지를 기존 후처리가 제거한 사례가 있었다. 원응답과 최종 응답의 품질을 구분한다.
- 생성기 유보와 서비스 근거 판정이 충돌하면 오류가 될 수 있다. 생성기 반환만으로 서비스 연결 성공을 판단하지 않는다.
- 소수 가상 문항·단회 비교이며, 적재·캐시·출력 길이가 달라 속도 우열을 판단하지 않는다.
- 실험 구현은 요청마다 모델 객체를 만들었다. 운영 도입 시 객체 유지 방식·실패 처리·부하 검토가 필요하지만 이번에는 진행하지 않는다.
- Linux 배포, 실제 브라우저, 최신 후처리와의 전체 연결, 현재 서비스의 품질 동등성은 미확인이다.

## 보관과 재현 범위

실험 코드·테스트·전용 의존성·실행 안내는 최종 main 변경 목록에서 제외했다. 기존 [코드 보존 커밋](https://github.com/SpicyAutumn/SKN33-4th-1Team/tree/a2b07af4de8cae6fc44990ca7e68c5d415260ae9/experiments/langchain_generation_public)과 로컬 ZIP 보관본으로 복구할 수 있다. 과거 GitHub 이력을 삭제한 것은 아니다.

실제 원응답·서버 로그·개인 환경 기록은 공개하지 않는다. 따라서 이 문서나 코드 보관본만으로 과거 실측을 재계산할 수 없다. 코드 보관본은 현재 서비스 실행에 필요하지 않으며 재실행·유료 호출 승인도 아니다.
