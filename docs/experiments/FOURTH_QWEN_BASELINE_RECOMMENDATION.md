# docs: Qwen 27B 모델 전환 및 신규 baseline 채택 제안

## 제안 및 PR 범위

답변 모델을 실험에 사용한 Qwen 27B로 전환하고, 최신 서비스에 통합한 구성을 후속 개선의 신규 baseline으로 사용할 것을 권장합니다. 실험 당시 Ollama 모델 태그는 `qwen3.8:27b`입니다.

주요 근거는 기존 Dev120·Holdout120에서 확인한 응답 유형 일치와 정정·되묻기 처리 개선입니다. RAGAS에서는 Dev의 근거 충실도 개선을 확인했지만, 답변 관련성까지 일관되게 개선된 것은 아닙니다.

이 PR은 실험 결과와 모델 전환 권고를 공유하는 문서 PR입니다. 운영 모델 변경, 최신 통신 규약 적용, 배포 완료를 의미하지 않습니다.

## 1. 최초 baseline 대비 모델 교체 결과

| 구성 | Dev 유형 일치 | 기존 Holdout 유형 일치 |
|---|---:|---:|
| 최초 EXAONE baseline | 55/120 (45.8%) | 46/120 (38.3%) |
| EXAONE 고정 최종 수정 후보 | 88/120 (73.3%) | 53/120 (44.2%) |
| **최초 baseline + Qwen 모델 교체** | **104/120 (86.7%)** | **98/120 (81.7%)** |

EXAONE을 고정한 수정은 Dev에서는 개선됐으나 Holdout 개선 폭이 작고 내용 회귀가 발견되어 채택하지 않았습니다. Qwen 비교에는 해당 수정 후보를 합치지 않았습니다. 최초 baseline의 프롬프트·서비스·후처리·질문·기대 라벨·검색 문맥을 유지하고 Ollama 요청의 모델 값만 교체했습니다.

정정·되묻기 응답은 유형명뿐 아니라 실제 답변과 검색 근거를 대조했습니다.

| 실제 처리 검토 | 최초 EXAONE baseline | Qwen |
|---|---:|---:|
| Dev 정정 | 8/20 | 16/20 |
| Dev 되묻기 | 3/20 | 16/20 |
| **Dev 합계** | **11/40** | **32/40** |
| Holdout 정정 | 11/20 | 13/20 |
| Holdout 되묻기 | 1/20 | 10/20 |
| **Holdout 합계** | **12/40** | **23/40** |

유형 일치율은 전체 사실 정확도가 아닙니다. 특히 Holdout 정정 유형 일치는3→17건이지만 내용 통과는11→13건이므로, 출력 분류 개선과 내용 개선을 구분합니다. 내용 검토는 Codex의 근거 대조에 따른 잠정 판정이며 독립적인 사람의 블라인드 평가는 아닙니다.

## 2. 사후 RAGAS 결과와 한국어 역질문 재평가

Dev·Holdout 각각 일반 답변 기대20문항과 정정 기대20문항을 전부 선정했습니다. 아래 각 점수는40문항 평균이며120문항 전체 점수가 아닙니다. 저장된 최종 서비스 `message`를 평가했고 답변 생성·검색은 재실행하지 않았습니다. EXAONE 응답은 모두 최초 baseline이며 최종 수정 후보가 아닙니다.

| 지표 | Dev EXAONE → Qwen | Holdout EXAONE → Qwen |
|---|---:|---:|
| Faithfulness — 본문만 | 0.8378 → **0.9272** | 0.8639 → 0.8831 |
| Faithfulness — 제목+본문 | 0.8198 → **0.9203** | 0.8769 → 0.9160 |
| AnswerRelevancy — 공식 기본 프롬프트 | 0.3464 → 0.3380 | 0.3684 → 0.3924 |
| AnswerRelevancy — 한국어 역질문 지시 추가 | **0.6815 → 0.5909** | 0.5887 → 0.6170 |

- **근거 충실도:** Dev에서는 두 조건 모두 개선 신호가 있습니다. 제목+본문 조건의 차이는+0.1005, 문항별 paired bootstrap 95% 구간은[+0.0491,+0.1550]입니다. Holdout 차이+0.0391의 구간은[-0.0249,+0.1037]로 뚜렷한 개선을 확정하지 못했습니다.
- **답변 관련성:** 공식 기본 프롬프트의 역질문이 주로 한국어 이외 언어로 생성되어, 동일한 저장 답변 전체에 한국어 역질문 지시를 추가해 보완 평가했습니다. 모델 비교와 프레임워크 비교를 합친240개 응답의 역질문720개가 모두 한국어로 생성됐고 모든 그룹 평균이 상승했습니다. 기존0.3대 점수를 그대로 낮은 서비스 품질로 해석하지 않습니다.
- **불리한 결과도 공개:** 한국어 조건에서 Dev는 EXAONE이 높았고 Qwen−EXAONE 차이의 구간은[-0.1577,-0.0344]입니다. Holdout은 Qwen이 소폭 높았으나 구간[-0.0333,+0.0990]에0이 포함됩니다. 답변 관련성은 Qwen 전환의 일관된 우위 근거로 제시하지 않습니다.

설치된 RAGAS0.4.3의 지표 구현·기본 프롬프트4파일은 공식 소스와 해시가 일치했습니다. 최초 평가는 공식 기본 프롬프트를 사용했고, 한국어 재평가는 **공식 계산식과 예시를 유지하되 언어 지시를 추가한 보완 평가**입니다. 두 결과를 구분하여 보존했습니다. 제목+본문 Faithfulness도 제목 누락 영향을 확인하기 위한 추가 진단이며 최초 결과를 덮어쓰지 않았습니다.

관련성 지표는 정당한 유보도0점 처리할 수 있고, 검색 근거 없이 질문에 직접 답한 응답에는 높은 점수를 줄 수 있습니다. 반대로 나전칠기처럼 근거가 있는데도 유보한 실제 실패도 있었습니다. 지표에 불리한 모든 사례를 평가 오류로 간주하지 않습니다. RAGAS는 유형·내용 평가를 보완하는 지표로 사용합니다.

## 3. Qwen 이후 LangChain·LangGraph 실험

| Dev 비교 | Qwen baseline | LangChain + 본문 보충 | LangGraph 판단·작성 분리 |
|---|---:|---:|---:|
| 유형 일치 | 104/120 | 107/120 | 107/120* |
| 정정·되묻기 내용 통과 | 32/40 | 31/40 | 31/40 |
| Faithfulness — 일반·정정40, 제목+본문 | 0.9203 | 0.9373 | 0.8504 |
| AnswerRelevancy — 동일40, 한국어 역질문 | 0.5909 | 0.6009 | 0.6226 |
| 생성 모델 호출 | 106회 | 106회 | 142회 |
| 입력 토큰 | 265,357 | 449,099 | 273,672 |

*LangGraph의 상태·정정 분리 출력을 사전에 정한 보고용 규칙으로 기존 유형에 환산했습니다.

LangChain은 인접 본문 보충으로 일반 답변20의 Faithfulness가0.8812→0.9534로 개선됐습니다. 다만 전체 선정40의 개선은 불확실하고 핵심 정정·되묻기의 뚜렷한 순개선은 확인하지 못했습니다. 입력 토큰은69.2%, 동일106건의 HTTP 평균은9.715→12.691초로 늘었습니다. 순수 LangChain 연결은 저장 응답 재생에서120/120 동등했으며, 품질 변화는 문맥 보충을 포함한 구성의 효과입니다.

LangGraph는 한국어 관련성 평균이 올랐지만 Qwen과의 차이 구간에0이 포함됩니다. 근거 충실도는 하락했고 실제 근거 없는 정정과 평가자의 오판이 함께 관찰됐습니다. 호출 수는약34% 늘었습니다. 전체120건 평균 시간은8.582→8.285초로 줄었으나, 판단·작성2회를 호출한 동일33문항에서는11.355→16.696초로 늘었습니다. 모든 시간 지표가 악화됐다고 주장하지 않습니다.

**현재 실험 후보를 품질 개선 목적으로 그대로 도입하는 것은 권장하지 않습니다.** 일부 개선은 있으나 비용 증가를 정당화할 전반적인 개선 근거가 부족합니다. 프레임워크 일반의 효용에 대한 결론은 아니며 두 후보의 Holdout은 평가하지 않았습니다.

## 4. 실험 환경과 적용 한계

| 항목 | 조건 |
|---|---|
| 평가 기준 | 4차 작업 초기에 합의한 최초 baseline, 기존 `0.3.0-draft` ServiceResponse |
| 기존 모델 | `exaone3.5:7.8b-instruct-q8_0` |
| 비교 모델 | Ollama 태그 `qwen3.8:27b`, 27.3B, Q4_K_M |
| 생성 서버 | Runpod–Ollama, A40은 사용자 제공 환경 정보이며 GPU 실측은 별도 수집하지 않음 |
| Ollama 버전 | EXAONE 저장 기록0.34.0 / Qwen 실행0.34.1 |
| 실행 방식 | Windows 격리 worktree의 Python 가상환경에서 Runpod Ollama 직접 호출 |
| 생성 설정 | 모델 교체 비교: `think=false`, `temperature=0`, `num_predict=640`, `general` |
| 검색 조건 | 저장 검색 결과·순서 고정, `top_k=3`; 검색 재실행 없음 |
| Qwen 호출 | Dev106회·Holdout113회, 오류·재시도0건; 나머지는 기존 규칙에서 처리 |
| 사전 검증 | 저장 EXAONE 응답 재생의 서비스 출력 동등성 Dev120/120·Holdout120/120 확인, 코드·입력 해시 동결 |
| 평가 모델 | RAGAS0.4.3, `gpt-4.1-mini-2025-04-14`, `text-embedding-3-small`, temperature0, strictness3 |

실험 모델 digest는 `22130167c4c20e20c7b71454612966ca8e8171e9b3cc8ab6ce8aa6cbfec79643`입니다. 런타임 metadata의 family는 `qwen35`였습니다. 모델 명칭은 실제 로컬 태그 기준이며 배포 시 태그뿐 아니라 digest·양자화·가중치 출처를 확인해야 합니다.

EXAONE과 Qwen은 실행 시점·모델 크기·양자화·Ollama 버전이 다릅니다. 동일 호출 대상의 서버 처리 평균은 Dev9.148→8.898초, Holdout8.359→8.685초였지만 캐시·부하를 통제한 속도 우열 비교는 아닙니다. Docker 프록시·React 화면·실시간 검색·동시 부하를 포함한 검증도 아닙니다.

Qwen 원응답 스키마 준수는 Dev89/106·Holdout90/113으로 EXAONE의106/106·112/113보다 낮았습니다. `related_topic_candidates`를 빈 배열로 제한하는 스키마와 해당 필드 작성을 유도하는 프롬프트의 불일치가 남아 있습니다. 기존 후처리로 실행 오류는 없었으나 운영 적용 전 정리·재검증이 필요합니다.

## 5. 신규 통신 규약 대응과 후속 작업

실험 당시에도 기존 RAG 출력 계약은 존재했습니다. 이번 결과는 **최초 평가 baseline의 모델 비교이며, 이후 정리된 신규 웹 API 통신 규약과 최신 서비스까지 통합 검증한 결과가 아닙니다.** 저장소 최초 커밋과 완전히 동일하다는 의미도 아닙니다.

모델 전환 후 기존 RAG 흐름을 기반으로 다음 작업을 별도로 진행할 것을 제안합니다.

1. 모델·생성 설정을 고정하고 최신 통신 규약에 맞게 답변 유형, 정정·되묻기, 출처 필드를 검증합니다.
2. `interaction_id`·`clarification_context` 전달과 후속 질문 처리를 API–RAG 구간에서 연결·검증합니다.
3. 타임아웃과 검색·생성 실패 응답을 규약에 맞추고, 프롬프트–스키마 불일치를 해결합니다.
4. 최신 검색·후처리·Docker 환경에서 회귀 평가와 실제 응답시간을 확인한 뒤 그 구성을 신규 baseline으로 고정합니다.

통신 규약 대응을 위해 LangChain/LangGraph 도입이 필수인 것은 아닙니다. 기존 점수가 최신 통합 환경에서도 그대로 유지된다고 가정하지 않습니다.
