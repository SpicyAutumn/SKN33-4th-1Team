## 4. 모델 외 원인과 라벨 한계

**011/020은 기존 후처리의 오정정이다.** 질문은 이미 올바른 내용을 확인하는 형식이다. Qwen 원출력은 answered, premise_correction=null로 정상 동의했지만, 기존 `_normalize_corrected_premise`가 동의 표현을 제거하고 corrected_premise 및 정정 필드를 생성했다. 최종 유형 오류를 Qwen의 의미 분류 실패로 돌리면 안 된다. 관련 코드: `src/rag_service/ollama_generator.py`의 `_normalize_corrected_premise` 및 호출부(이번 평가 시 307, 433, 440행). 이번 실험에서는 수정하지 않았다.

**040의 기대 설명은 1249년, 실제 제공 청원군 자료는 1259년이다.** 두 모델 모두 제공 근거의 1259년을 따랐다. 이를 연도 환각으로 세지 않았다. 원 라벨을 변경해 점수를 올리지 않았으며 Qwen 부분 감점은 별도 한자 추가 때문이다.

002/016도 질문 대상에 맞는 검색 근거가 충분하지 않다. 일반 답변 기대 불일치를 모두 모델 실패로 해석하지 않는다.

유형 점수에 나타나지 않는 일반 답변 관찰:

- 008: 두 모델 모두 출처의 '바장조'에 근거 없는 'B-flat major' 병기를 추가했다. 한국어 핵심 용어와 answered 유형만 보면 놓치는 오류다.
- 015: Qwen의 '조합원을擁했던' 한자 혼입이 남고, 두 모델 모두 2011년 설명을 현재로 이어 최신 상황처럼 보이게 한다.
- 001: Qwen은 내장택의 토지 재원과 내장택보의 이자 운용을 구분했다.
- 003: EXAONE의 러시아 활동을 유럽으로 확대하는 서술은 Qwen에서 사라졌다.

안전 081/089와 범위 밖 104/106/109/111/112/113/117은 insufficient_evidence로 남았다. 금지된 요청을 실제 수행했는지와 계약상 거절 유형이 맞는지는 별개다. 이번 유형표는 후자를 측정한다.

## 6. 결론과 후속 우선순위

Dev 유형 55→104와 별개로 holdout도 46→98로 개선됐다. 되묻기의 실제 처리 개선도 확인된다. 다만 Dev의 내용 통과 11→32에 비해 holdout은 12→23으로 작으며, 정정은 출력 유형을 제대로 전달하는 개선의 비중이 크다. 모든 의미 판단 문제가 해결됐다는 결론은 아니다.

1. 현재 Docker/LangGraph 경로에서 동일 Qwen의 출력 계약·시간·실제 응답 전달을 별도 확인한다. 본 평가를 LangGraph 개선 결과로 인용하지 않는다.
2. 011/020에서 확인한 정상 답변을 정정으로 바꾸는 후처리 문제를 먼저 좁혀 수정 후보로 다룬다. 이번 점수에는 수정 효과를 포함하지 않는다.
3. 되묻기 선택지의 대상/관계 오류와 정정 설명의 근거 밖 부가 사실, 검색 실패를 각각 구분해 개선한다. 이미 본 holdout에 반복 튜닝한 뒤 이를 새 독립 검증이라고 부르지 않는다.
