# 최초 baseline과 최종 코드의 Holdout 120문항 비교 설계

> 공유 안내: 이 문서는 실행 당시의 결과 기록입니다. Dev120·Holdout120 질문 세트는 팀 Google Drive에 ZIP으로 공유했습니다. 문서에 언급된 `outputs/`·`experiments/` 원자료는 로컬 보관이며 이 문서 PR에 포함하지 않습니다. 당시의 미게시·후속 평가 미실행 표기는 해당 기록 작성 시점을 뜻합니다. 최신 종합 판단은 [모델 전환 제안](FOURTH_QWEN_BASELINE_RECOMMENDATION.md)을 참고해 주세요.

2026-09-15. 비교 대상은 Dev에서 55/120이었던 최초 코드와, 정규화 수정 후 88/120이었던 최종 코드 두 개다. 79건 중간 버전은 실행하지 않는다. 숫자는 Dev 점수에 따른 버전 식별명이며 Holdout의 예상 점수가 아니다.

## 문항 생성과 고정

- 6개 응답 유형을 각각 20문항, 총 120문항으로 구성한다. 유형 비중은 Dev와 같다.
- 기존 3차·4차 평가 질문 및 대표/참조 문서, 4차 Dev에서 이미 검색·검토한 문서와 제목을 제외한다.
- 코드의 성공 사례 대신 로컬 AKS 문서 풀에서 먼저 자료를 추출한다. 시드는 `2026091501`이다.
- 역사·정치, 종교·철학, 예술·체육, 문학·언어·출판, 생활·경제·사회, 과학·교육·지리의 6개 묶음에서 문서를 10개씩 고른다. 각 묶음에서 같은 시대 대분류는 최대 3개, 같은 항목 유형은 최대 4개다.
- 제목 길이 2~35자, 정의 길이 20~250자인 문서를 대상으로 추출했다. 이 조건은 한 글자 항목과 아주 길거나 짧은 정의를 제외하는 표본 제한이다.
- 추출 순서에 따라 일반 답변·정정·근거 부족의 문항 역할을 돌아가며 배정한다. 각 역할은 20개 문서를 사용한다. 정정에 유리한 문서를 보고 역할을 고르지 않는다.
- 일반 답변 20개와 정정 20개는 각각 정의 근거 10개, 본문 근거 10개로 작성한다. 본문에 반박이 있는데 정의만 이용하는 코드가 놓치는 사례도 그대로 포함한다.
- 되묻기는 대상/위치/비교 대상 누락, 첨부 없는 지시, 동명 항목, 독립된 복합 요청을 포함한다. 일반 답변에는 올바른 전제 확인과 부정형 설명도 넣는다.
- 안전 거절은 문서에 명시된 비공개 지시·자격증명 유출 및 prompt injection 범위에서 작성한다. 범위 밖에는 실시간 정보, 일반 기술·계산·문서 작성·예약 요청, 비밀값을 요구하지 않는 보안 용어 설명을 포함한다.

자료 기반 60문항의 메타데이터상 시대 대분류는 고려 4, 고대 4, 근대 13, 조선 17, 현대 13, 미상 9다. 시대가 복수로 표시된 문서는 첫 분류를 사용했으므로 역사적 시대를 엄밀하게 수동 재분류한 통계는 아니다. 총 13개 분야 대분류를 포함한다.

질문 길이는 16~66자, 평균 약 36.1자다. 정확한 질문 문자열 중복과 기존 대표/참조 문서 ID 중복은 0건이다. 고정 데이터는 `data/evaluation/aks4_rag_holdout_v2.draft.jsonl`이며 SHA-256은 `fd85352d798289c41f07d5abf1e53ce422b6a26652ffb223b8842863ca621ff8`이다.

## 독립성에 관한 제한

구현과 문항 작성을 같은 assistant가 수행했으므로 독립된 외부 출제자의 블라인드 평가와 같지 않다. 자료 추출을 먼저 하고, 결과를 보기 전에 문항·기대 동작·코드를 고정하는 방식으로 영향을 줄였다. 실행 결과가 나쁘다는 이유로 질문·라벨·코드를 바꾸지 않는다.

자료 기반 문항은 새로운 대상과 사실을 사용한다. 다만 안전·범위·지시 대상 누락 문항의 **정책 의도와 일부 표현 계열은 Dev와 공유**한다. 예를 들어 실제 자격증명 값을 요구하거나 인코딩해 공개하라는 요청은 동일 정책군이다. 정확한 문자열 중복 0건이나 낮은 문자 유사도가 의미적 독립성을 증명하지는 않는다. 이 군은 새로운 의미 관계만의 평가가 아니라 동일 정책의 다른 표현에 대한 평가도 포함한다.

분야 균등·유형 균등 구성은 실제 사용자 유입 분포를 대표하지 않는다. 자료 추출 결과에 생소한 지역 인물·문집이 포함되어 있으며, 실제 인기 질문 중심 세트와 난이도가 다를 수 있다. 전체 점수만으로 운영 정확도라고 부르지 않고 유형별 결과와 개선·퇴행 문항을 제시한다.

정답은 모두 assistant 작성 `draft`다. 일반 답변·정정 40건은 실제 원문 구절과 ID를 연결했다. 근거 부족 20건은 해당 항목과 요구된 상세 정보에 대한 제한적인 부재 판단이며 전체 인덱스에 답이 전혀 없음을 증명한 것은 아니다. 검색 결과에 답이 발견되면 라벨 결함으로 별도 기록한다. '봄'처럼 기본 의미를 택할지 동명 여부를 되물을지의 정책 경계도 별도 표시했다.

## 실행과 공정한 비교

1. 최초 baseline의 운영 파일을 Git HEAD에서 복원한 별도 스냅샷으로 만든다. 파일 해시가 최초 `baseline_v2.manifest.json`의 기록과 같음을 확인했다. 현재 작업 트리의 최종 코드도 별도 스냅샷으로 고정했다.
2. 두 스냅샷으로 과거 Dev 원응답을 재생해 baseline 120/120, 최종 120/120의 최종 응답 전체 일치를 확인했다. 재생한 기존 모델 요청은 각각 106개와 84개다. 이 검사는 Holdout 점수가 아니다.
3. 기존 EXAONE 모델의 digest, Ollama 버전, 프롬프트·설명 수준 프로필·출력 스키마, 검색 설정 및 로컬 인덱스 manifest를 확인한다. general, temperature=0, think=false를 유지한다.
4. Holdout은 120문항 × 두 버전으로 240건의 서비스 실행을 한다. 두 버전에서 한 문항의 request_id·interaction_id와 검색 결과를 공유한다. 검색 결과는 실제 검색 후 문항별로 한 번 저장하며 원문·순위·점수를 그대로 사용한다.
5. 모델 요청 payload 전체가 같은 경우 저장된 원응답을 공유한다. 요청이 다르면 별도 생성한다. 기대 유형·판정 근거·사전 지정 문서 ID는 서비스나 모델에 보내지 않는다.
6. 모델 HTTP 호출 전에 attempt 기록을 쓰고, 원응답 저장 후 다음 버전이 재사용한다. 불명확한 전송 실패는 자동으로 다시 과금 요청하지 않고 중단 기록을 남긴다. 완료한 문항은 재개 시 건너뛴다.
7. 진행 출력에는 완료 수·호출 수·오류 여부만 표시한다. 수집 완료 전 코드 수정이나 점수에 따른 문항 교체를 하지 않는다.

인덱스 전체를 과거 시점으로 복원한 실험은 아니다. 현재 검색 결과를 두 버전에 동일하게 제공해 비교하며, 검색 실패도 삭제하지 않는다. 캐시를 사용하는 최종 실행의 벽시계 시간이 짧더라도 실제 서비스의 지연 개선으로 해석하지 않는다.

## 평가 항목과 산출물

- 유형별 및 전체 기대 유형 일치.
- 같은 문항의 실패→성공, 성공→실패, 둘 다 성공, 둘 다 실패.
- 바뀐 응답의 본문·근거·정정 필드·되묻기 동작 검토. 정상 답변의 불필요한 정정과 과도한 축약도 확인한다.
- 원문에 있는 사실의 검색 실패, 모델 판단 실패, 정규화 변경, 라벨 문제를 구분한다.
- 실제 모델 호출·재사용·논리 검색 횟수와 실행 오류. SDK 내부 요청 수와 논리 검색 횟수를 혼동하지 않는다.
