# AI에게 검수 지시를 더 자세히 주면 오류를 잘 찾을까?

**결론: 이번에 확인한 문항에서는 개선되지 않았습니다. 보완 방식 B는 실제 서비스에 적용하지 않습니다.**

2026-09-10 사용자 검수 완료. 실제 서비스 코드는 변경하지 않았습니다.

## 1분 요약

- 원문과 답변을 비교하는 AI에게, 사람의 관계와 사용 범위를 정확하게 살피라는 지시를 추가했습니다.
- 기존 방식과 보완 방식 모두 같은 오류를 놓쳤습니다.
- 다른 문항에서는 보완 방식의 설명에 원문으로 확정할 수 없는 신분이 추가됐습니다.
- 일부 문항은 인용 오류로 비교를 끝내지 못했습니다. 이 결과도 숨기지 않고 기록합니다.
- **실패 원인과 한계를 확인한 실험 결과**로 공유하며, 코드 검사 통과를 답변 품질 개선으로 표현하지 않습니다.

```text
오류 발견 → 지시문 보완 → 같은 문항으로 비교 → 사람 검수
                                              │
                           ┌──────────────────┴───────────┐
                           ▼                              ▼
                   개선 확인 못함                  일부 비교 미완료
                           └──────────────────┬───────────┘
                                              ▼
                                B 적용 보류가 아닌 '미채택'
                                결과·코드·한계를 팀에 공유
```

## 질문과 설계

생성 답변의 주장을 원문과 비교하는 검증 모델이, 제한·관계 보존 지시를 추가하면 오류를 더 잘 발견하는지 확인했다. 기존 A와 의미 지시 추가 B를 같은 개발 문항에 적용했다. 인용 보완 지시는 이 비교에 섞지 않았다. 사람이 선택한 주장 단위 평가이며 자동 주장 추출이나 서비스 전체 평가가 아니다.

이전에 확보한 실제 답변 발췌 10개와 작성 대조 예시 2개를 사람이 검수했다. 이번 최소 비교는 그중 실제 발췌 2개와 작성 예시 1개다. 모델 생성과 검증은 같은 계열·모델로 수행되어 독립 검증으로 해석할 수 없다.

## 관측 결과와 확정 결론

| 문항 | 기존 A | 의미 보완 B | 사용자 검수 |
| --- | --- | --- | --- |
| V02 사용 대상 제한 | 원문과 충돌하는 주장을 '근거 있음'으로 잘못 판정 | 같은 오류 놓침 | 두 방식 모두 개선 미확인 |
| V01 노래를 부른 사람·상황 | 판정은 맞지만 설명의 관계 표현은 모호할 수 있음 | 판정은 맞지만 설명에서 신분을 단정함 | A가 B보다 원문에 부합. B 설명은 오류 |
| V03 추정 표현(직접 만든 예시) | 원문의 떨어진 구절을 합쳐 인용 검사 실패 | 실행하지 못함 | 비교 결론을 내릴 수 없음 |

인용 문자열이 원문에 존재해도 판정·설명이 맞는 것은 아니었다. 의미 보완 지시로 이번 오류가 해결되지 않았으므로 B를 운영 채택하지 않는다. 이는 A의 운영 신뢰성 승인도 아니며 모든 모델에서 개선이 불가능하다는 결론도 아니다.

이 표의 상세 근거는 [실험 과정·실제 응답](SEMANTIC_VERIFIER_JOURNEY.md)과 연결된 연구 증거 자료에서 확인할 수 있습니다. 당시 입력한 원문 청크와 두 세션의 실제 출력을 별도 공개본으로 구성했으며 이용 범위·제외 항목을 함께 명시했습니다.

## 다시 확인할 때 필요한 실험 조건

아래 값은 실험을 비교할 때 유지할 설정입니다. **가장 좋은 값으로 찾아낸 결과는 아닙니다.** `num_ctx`는 한 번에 처리할 글의 분량, `temperature`·`seed`는 출력의 무작위성을 조절하는 설정, `num_predict`는 답변 길이 상한입니다. 고정 설정이라도 완전히 같은 출력은 보장하지 않습니다.

- 모델: exaone3.5:7.8b-instruct-q8_0, Ollama 0.33.3, NVIDIA A40.
- Python 3.12.13, requests 2.34.2.
- num_ctx 32768, temperature 0, seed 42, num_predict 1024, stream false, JSON Schema 출력.
- 첫 검증: 준비 1 + 평가 3 = 4회, 인용 실패 후 중단.
- 비교: 준비 1 + 평가 5 = 6회, V03-A 인용 실패 후 중단, V03-B 미실행.
- 두 세션 합계 10회이며 프로젝트 이전 모든 실험의 합계는 아니다.
- 서버 종료 사용자 확인 완료. 최종 청구액은 검증하지 않았으며 호출 시간으로 비용을 대신 추정하지 않는다.

| 문항 | A/B 입력 토큰 | A/B 출력 토큰 | A/B 클라이언트 경과 초 |
| --- | --- | --- | --- |
| V02 | 1286 / 1477 | 186 / 175 | 7.766 / 7.609 |
| V01 | 1459 / 1650 | 197 / 171 | 8.937 / 7.594 |

토큰은 AI가 글을 처리하는 단위입니다. B에 지시를 추가해 입력이 191토큰 늘었지만, 답변은 더 짧았고 이전 입력을 재사용하는 정도(캐시)도 달랐습니다. 따라서 시간이 짧게 측정됐다는 이유만으로 B가 더 빠르다고 판단할 수 없습니다. 한 번씩만 비교했고 이미 살펴본 문항을 사용했으므로, 새로운 질문에서도 같은 결과가 나온다고 일반화하지 않습니다.

## 공유용 도구의 범위

[실험 도구](../experiments/semantic_verifier/README.md)는 합성 입력으로 독립 동작 검사와 외부 자료 경로 입력을 지원한다. 과거 결과를 생성한 로컬 코드와 분리한 버전이며 공유용 버전의 실서버 재평가는 수행하지 않았다. 원본 결과는 덮어쓰지 않는다. 새 도구 테스트 통과를 모델 품질 개선으로 해석하지 않는다.

| 결과를 과장하지 않았는가? | '개선 없음'과 '실행하지 못함'을 구분했는지 확인 |
| 코드가 맞는 것과 답변이 맞는 것을 구분했는가? | 인용 검사 통과만으로 판정·설명을 승인하지 않았는지 확인 |
| 같은 실험을 다시 할 수 있는가? | 모델·지시문·설정은 확인 가능하되 실제 원문 자료는 별도 접근이 필요함을 확인 |
| 실제 서비스가 바뀌는가? | 이 변경은 실험 도구와 기록 공유이며 운영 반영은 아님 |

실험 결론과 미실행 범위가 명확한지, 정답이 추론 입력과 분리되는지, 형식 검사와 사람 의미 검수를 혼동하지 않는지, 원문 자료를 별도로 관리하면서 재현 가능성의 한계를 설명했는지 확인해 주세요. 코드 리뷰 후 필요하면 후속 실험 범위를 별도 합의합니다. 자동 운영 반영·자동 병합은 하지 않습니다.
